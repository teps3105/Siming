# 6.1 架構總覽

《司業命緣》是 Godot 4.7 加 Rust 的專案：遊戲規則全部在純 Rust 的模擬核心 `siming-sim`，Godot 只負責呈現、輸入與儲存，兩者以一個 GDExtension 橋接 crate 相連。本節說明分層、目錄與依賴原則；各層細節見 6.2–6.9。

## 分層

```
┌──────────── game/（Godot 4.7 專案，GDScript）────────────┐
│  app      啟動與裝配                                      │
│  sim      橋接入口：持有 SimWorld、依速度推進、轉發事件      │
│  map      地形網格、水墨著色器、地圖模式、場域烘焙、標籤     │
│  objects  建築、軍隊、劍光                                 │
│  spectacle 奇觀佇列與特效                                  │
│  input    動作層、鏡頭、選取、權能目標選擇                   │
│  hud      頂欄、權能列、傳聞、卡片、輪迴台、天書、結算        │
│  storage  存檔、設定、天書                                 │
│  locale   介面字串與事件模板    ui_kit  字型與共用元件       │
└────────────────────────┬────────────────────────────────┘
                         │ SimWorld（GDExtension 類別）
┌────────────────────────▼────────────────────────────────┐
│  siming-gdext（Rust cdylib）：型別轉換，不含規則           │
└────────────────────────┬────────────────────────────────┘
                         │ 唯讀狀態、事件 ◀──── ▶ Command
┌────────────────────────▼────────────────────────────────┐
│  siming-sim（純 Rust 函式庫：無引擎、無 IO、確定性）        │
│  params  worldgen  calendar  soul  people  powers  field │
│  war  cosmos  command  ledger  save                      │
└──────────────────────────────────────────────────────────┘
          ▲                                    ▲
  siming-cli（無頭：生成、模擬、統計、重播、匯出圖檔）   tests/
```

`field` 模組是 [6.9 場域框架](6.9-場域框架.md)：所有州域與格域的「場」（2.7）的識別、統一讀寫入口、傳輸運算核心與重算鏈；其他系統是場的讀取者與寫入者。`map` 模組以同一條烘焙與著色路徑呈現任一場。

## 目錄

```
game/                        唯一的 Godot 根（res://）
  project.godot
  app/scenes/bootstrap.tscn  遊戲入口
  modules/<模組>/            scenes/ code/ resources/ assets/ generated/ tests/
  modules/sim/resources/siming.gdextension   擴充載入設定
  modules/sim/generated/     橋接程式庫（由建置工具產生，不提交）
  addons/godot_ai/           編輯器 MCP 插件（第三方，不修改）
  tests/                     跨模組測試
native/sim/rust/             Cargo workspace
  crates/sim/                siming-sim（lib）
    src/params.rs            7.1 參數總表的唯一程式對應
    src/worldgen/            2.2
    src/field/               2.7、6.9（識別、核心、衍生場、重算鏈）
    src/...                  其餘模組見 6.2、6.3
    data/                    命名字庫（7.3）
  crates/cli/                siming-cli（bin）
  crates/gdext/              siming-gdext（cdylib，6.4）
tools/
  native_build/              建置橋接程式庫並放進 game/（6.6）
  checks/                    規範檢查（6.7）
  font_subset/               字型子集化（6.6）
docs/                        本 GDD
builds/                      匯出成品（不提交）
```

Godot 端的模組依第一欄的責任切分；一個模組的程式、場景、資源與素材都放在自己的目錄下，跨模組只使用對方 `code/` 中公開的腳本入口。目前已建立的模組是 `sim`、`map`、`input`、`hud`、`locale`、`ui_kit`，其餘在實作對應功能時建立。

## 依賴原則

| 單元 | 允許 | 禁止 |
|---|---|---|
| siming-sim | serde、serde_json（只用於編譯期嵌入的字庫）、rand、rand_chacha、bincode、miniz_oxide、smallvec、rustc-hash（FxHasher） | godot、任何 IO、執行緒、時間 |
| siming-gdext | siming-sim、godot（gdext 0.5，`api-4-7`）、steamworks（僅 `steam` feature，9.2） | 遊戲規則 |
| siming-cli | siming-sim、png、clap | godot |
| Godot 模組 | `SimWorld`、Godot 內建功能 | 遊戲規則、直接讀寫模擬狀態 |

- 規則只有一份：任何會改變世界雜湊（6.5）的計算都在 `siming-sim`。Godot 端與橋接只做顯示用的換算，例如把高度陣列轉成貼圖。
- 模組之間的依賴不得成環；`app` 只做裝配，不承擔功能。
- `sim` 模組的 `SimHost` 是 Godot 端唯一建立與推進 `SimWorld` 的地方；其他模組由它取得世界後只做查詢，不呼叫 `create`、`step` 與指令方法。

## 理由

背景：呈現層原以 Bevy 與 bevy_egui 實作，介面元件、輸入、搖桿、音訊與匯出都要自行組裝。選擇：模擬核心維持純 Rust，呈現層改用 Godot，以 GDExtension 相連（決策 #39，6.10）。原因：模擬核心的確定性測試與無頭工具不依賴引擎，可原樣保留；介面、輸入、音訊與 Steam Deck 匯出改用 Godot 內建功能，免去自製。來源：godot-rust 手冊 <https://godot-rust.github.io/book/>。
