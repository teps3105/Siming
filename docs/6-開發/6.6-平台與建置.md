# 6.6 平台與建置

遊戲以 Godot 4.7.1 匯出，目標是 Windows 與 Linux（含 Steam Deck）；Rust 部分用 stable 工具鏈建置成 GDExtension 程式庫後由 Godot 載入。本節列出目標平台、建置步驟、字型子集化與持續整合的工作。

## 目標平台

| 目標 | 建置 | 備註 |
|---|---|---|
| Windows x64（Demo 必要） | 橋接程式庫 release ＋ Godot 匯出 | 9.4 |
| Linux x64、Steam Deck | 同上，於 Linux 建置 | 同一份 Linux 建置 |
| macOS | — | Demo 不提供 |
| 瀏覽器 | — | 不在範圍（決策 #39，6.10） |
| 無頭 | `cargo run -p siming-cli --release -- <子命令>` | 持續整合與平衡調整；不需要 Godot |

## 工具版本

| 工具 | 版本 | 來源 |
|---|---|---|
| Godot | 4.7.1 stable | 編輯器與匯出範本 |
| Rust | stable，1.94 以上 | `godot` crate 0.5.5 的 `rust-version` |
| `godot` crate（gdext） | 0.5.5，feature `api-4-7` | <https://crates.io/crates/godot/0.5.5> |

## 建置橋接程式庫

```
python tools/native_build/build.py            # debug
python tools/native_build/build.py --release  # release
```

1. 在 `native/sim/rust/` 執行 `cargo build -p siming-gdext`。
2. 把 `target/<設定>/` 下的程式庫複製到 `game/modules/sim/generated/`，檔名為 `siming_gdext.<debug|release>.dll`（Linux 為 `libsiming_gdext.<debug|release>.so`）。
3. `game/modules/sim/resources/siming.gdextension` 依平台與設定載入對應檔案。

`generated/` 下的程式庫不提交；取得原始碼後要先建置一次，編輯器才認得 `SimWorld`。擴充設定為 `reloadable = true`，編輯器開著時可以直接重建並覆寫程式庫；但新增或改名的方法要重啟編輯器才認得（實測：未重啟時腳本報「方法不存在」）。從編輯器執行中的遊戲會鎖住程式庫，重建前先停止遊戲。

## 匯出

1. 以 release 建置橋接程式庫。
2. Godot 以 `game/export_presets.cfg` 的設定匯出到 `builds/<目標>/`（`windows`、`linux`）。
3. Steam 版另以 `--features steam` 建置橋接程式庫，並附上 Steamworks 再發行檔（9.2）。

`export_presets.cfg` 在第一次設定匯出時建立。

## 字型子集化（`tools/font_subset/subset_font.py`）

1. 掃描下列檔案中的 CJK 字元：
   - `native/sim/rust/crates/**/*.rs`
   - `native/sim/rust/crates/sim/data/*.json`（命名字庫，7.3）
   - `game/modules/locale/resources/*.json`（事件模板與介面字串，8.6）
2. 加上常用字表（常用字 4,808 字，確保數字與標點）。
3. 以 fontTools 產生 `game/modules/ui_kit/assets/fonts/wenkai_tc_subset.ttf`、`wenkai_sc_subset.ttf`（9.5）。
4. 子集字型提交到版本庫；原始字型不提交。
5. 驗收：子集字型 ≤ 3.5 MB。

GDScript 與場景檔中寫死的中文字不在掃描範圍；顯示文字一律放 `locale` 的 JSON（9.5）。

## 持續整合（GitHub Actions）

流程檔在 `.github/workflows/`，Windows（`windows-latest`）與 Linux（`ubuntu-latest`）各跑一次。檔案尚未在 GitHub 上實際跑過；本機只驗過 YAML 語法與每一步的指令（Windows）。

| 檔案 | 工作 | 內容 |
|---|---|---|
| `ci.yml` | `check` | `check_hant.py`、`check_trace.py`、`check_palette.py`；`cargo fmt --all --check`；`cargo clippy --release --workspace --all-targets -D warnings`；`cargo test --release --workspace`（跳過 `gdd_6_8_medium_generation_within_budget`）；該項再以 `--test-threads=1` 單獨跑 |
| `ci.yml` | `determinism` | `cargo test --release -p siming-sim --test determinism --test save`；兩個平台各驗 6.5 的固定期望雜湊（`gdd_6_5_golden_hash_is_stable_across_platforms`），任一邊不符即失敗 |
| `godot-tests.yml` | `godot-tests` | `build.py` 建 debug 橋接程式庫；下載官方發行檔 Godot（版本號為檔內變數 `GODOT_VERSION`）；`--headless --import` 建匯入快取；`tools/tests/run.py --godot …`；逐案結果存為 artifact |
| `build.yml` | `bridge-release` | `build.py --release`，橋接程式庫存為 artifact |
| `balance.yml` | `balance` | `siming-cli sim` 跑種子 1、2、3 各 1 運，統計報表存為 artifact；手動或每週日觸發，不判失敗 |

世界生成效能預算（`gdd_6_8_medium_generation_within_budget`，中尺寸生成 ≤ 1.5 秒）在測試並行時因爭用 CPU 超時，單獨跑通過，所以主測試跳過它，再單獨以單執行緒執行。

現況與已知缺口：

- `cargo fmt --check` 一步設為不擋（`continue-on-error`）：現有程式未經 rustfmt 整理。整理後移除該設定。
- 6.6 原表的 `build` 尚缺 Godot 匯出（`game/export_presets.cfg` 未建立）與 `steam` feature（`siming-gdext` 尚無此 feature）。
- 6.6 原表的 `l10n` 未建立：`t2s.py` 與繁簡字庫條目數檢查還不存在（簡體字檢查已由 `check_hant.py` 在 `check` 涵蓋）。
- `determinism` 的跨平台比對靠固定期望雜湊，不是兩個平台的輸出互相比對。
