# 6.4 呈現層

呈現層是 `game/` 下的 Godot 4.7 專案（Forward+ 渲染），以 GDScript 撰寫，經由 GDExtension 類別 `SimWorld` 讀取模擬世界。本節規定橋接介面、Godot 模組的職責、模擬驅動方式與地圖資料契約；畫面規格見第 5 章。

## 橋接：`SimWorld`

`siming-gdext`（`native/sim/rust/crates/gdext/`）把一個 `Sim` 包成 Godot 的 `RefCounted` 類別 `SimWorld`。載入設定在 `game/modules/sim/resources/siming.gdextension`。

| 方法 | 回傳 | 用途 |
|---|---|---|
| `create(seed, size)` | `String`（空字串為成功，否則為失敗原因） | 開天：世界生成、開天、預跑（4.6）；`size` 為 `small`、`medium`、`large` |
| `create_with(options)` | `String`（同上） | 開天，開局選項全部由字典指定：`seed`、`name`、`size`、`land_ratio`、`relief`、`humidity`、`era`（`ancient`、`middle`、`decline`）；沒給的取預設值，數值夾在 4.6 的範圍內 |
| `world_options()` | `Dictionary` | 這個世界的開局選項（鍵同上；`seed` 是品質檢查重試後實際使用的種子） |
| `random_world_name(seed)` | `String` | 由種子取的世界名（靜態方法，7.3） |
| `save_text()` | `String` | 存檔的內容（JSON 文字，6.5） |
| `load_begin(text)` | `String`（空字串為成功） | 讀檔第一步：檢查存檔並重新開天；完成前原本的世界照舊可用（4.8） |
| `load_step(max_ticks)` | `Dictionary`：`done`、`progress`、`error` | 讀檔第二步：最多重播這麼多個月；到位並通過雜湊比對後，世界換成讀出來的這一個 |
| `is_ready()` | `bool` | 是否已有世界 |
| `step(months)` | — | 推進指定月數（6.3） |
| `tick()`、`date_text()`、`date_short()` | `int`、`String`、`String` | 目前 tick、完整日期與題簽用的日期（2.6「日期顯示」） |
| `hash_hex()` | `String` | 世界雜湊，16 個十六進位字元（6.5） |
| `grid_size()` | `Vector2i` | 遊戲格的寬與高；地圖的世界座標以格為單位，x 向東、z 向南 |
| `terrain_max_height()`、`terrain_height_at(x, z)` | `float` | 高度縮放為 1 時的最高點與任一點的地形高度（取細化後的高度場，不含著色器的微細節） |

| `river_mesh()` | `Dictionary`：`positions`、`tangents`、`side_level`、`taper`、`indices` | 河流帶狀網格（5.3「河流」）；寬度由著色器依螢幕像素展開 |
| `relief_textures()` | `Dictionary`：`elevation_half`、`elevation_size`、`lake`、`climate`、`cover`、`climate_size`、`sea_level` | 跟著高度場換的貼圖（5.3「貼圖」）：高度（16 位元半精度，含整串多級縮圖，可直接建成 `FORMAT_RH` 的圖）、湖面遮罩、植被底色、地表覆蓋 |
| `data_textures()` | `Dictionary`：`aura`、`aura_scale`、`province_id` | 每世結算後換的貼圖：靈氣場與州郡 ID |
| `map_textures()` | `Dictionary`：上兩項的鍵，加 `elevation`（`PackedFloat32Array`） | 貼圖的原始資料，工具與測試用；地圖不用它 |
| `terrain_revision()`、`map_revision()` | `int`、`int` | 高度場換過幾次；地圖顯示的資料換過幾次（見「天地演變的換圖」） |
| `terrain_pending()`、`map_pending()` | `bool`、`bool` | 背景是否正在重算高度場；是否有任何一批在重算 |
| `poll_terrain()`、`flush_terrain()` | `bool`、— | 每幀呼叫，背景算好了就換上、回傳有沒有換，不等待；後者等到算好並換上（測試與工具用） |
| `paper_texture()` | `PackedByteArray` | 紙紋 512×512 RGBA8（靜態方法，8.3） |
| `province_colors()` | `PackedByteArray` | 州郡 ID → 淡彩的 256×1 RGBA8 查表（5.4 天下模式） |
| `province_at(x, z)` | `int` | 該點所在格的州郡 ID，水域或圖外為 -1 |
| `province_count()`、`province_info(id)` | `int`、`Dictionary` | 州郡數與單一州郡摘要（名稱、人口、承載、各氣場、城池等級、三教教化、治所位置與治所名、格數、地形組成） |
| `map_labels()` | `Array[Dictionary]` | 地圖標籤：`kind`、`text`、`pos`、`rank`、`path`（江河的幹流、山脈的走向；5.3「文字標籤」）；`kind` 含 `ocean`、`sea`、`lake`（水域，7.3） |
| `ley_lines()`、`ley_nodes()` | `Array[Dictionary]` | 靈脈路徑與洞天福地（2.4、5.4） |
| `sects()` | `Array[Dictionary]` | 全部宗門（含已覆滅者，以 `alive` 區分）：`id`、`name`、`pos`（山門格心的世界座標）、`province`（山門所在州郡）、`node`（所在洞天福地名，無則空字串）、`members`、`prestige`（有效聲望）、`radius`（勢力範圍半徑，步）、`range`（範圍內州郡 ID，`PackedInt32Array`）、`range_radius`（範圍圈半徑，格，為範圍內州郡格數之和的等面積圓半徑）、`evil`、`alive`（3.5、5.4、5.5） |
| `faith_colors()` | `PackedByteArray` | 三教模式的州郡著色表：州郡 ID → 淡彩的 256×1 RGBA8，alpha 為道教化濃度，0 表示不上色（5.4） |
| `total_population()`、`alive_person_count()` | `float`、`int` | 全世界人口、在世有名之人數 |
| `stats_world()`、`stats_provinces(sort, limit, descending)`、`province_roster(kind, value, limit)`、`stats_people()`、`people_where(kind, value, limit)`、`stats_sects()`、`stats_karma()`、`karma_roster(kind)`、`recent_counts(years)`、`recent_events(key, years, limit)` | `Dictionary` | 天下冊（5.10）的唯讀統計：只讀世界、不改任何狀態、不影響雜湊；欄位與定義見 5.10「現況」。實作在 `sim` 的 `stats.rs`，橋接在 `gdext` 的 `stats_api.rs`（`#[godot_api(secondary)]`） |
| `follow(soul, on)` | — | 關注或取消關注一個魂（4.7）；下一個 tick 開始前生效 |
| `drain_events()` | `Array[Dictionary]` | 取走新事件：`id`、`tick`、`kind`、`importance`、`province`（無為 −1）、`cell`（無為 −1）、`pos`（`Vector2` 地圖座標：有格取格中心，否則取州郡治所；兩者皆無則沒有此鍵）、`souls`（`PackedInt32Array`）、`date_era`（事件當時的紀元名）、`year`（紀元年，與天時儀日期簽同一算法）、`month`（1..12，2.6 曆法）、`persons`、`powers`（牽涉的人物、勢力編號，`PackedInt32Array`；州郡編號即 `province`）、`a_person`、`b_person`（兩位主角的人物編號，無為 −1）、`q_province`（`q` 那個州郡的編號，無為 −1）；主角（`a`）的身分取自事件發生當月月底（橋接逐月推進時記下，快轉一次推進多月仍是當時的樣子；讀檔重播的事件取現況）：`a_power`（所屬勢力名，君主與無勢力為空字串）、`a_role`（職分代號：`Ruler`、`Leader`、`Member`、`Rogue`、`Monk`、`Scholar`、`Demonic`、`Beast`、`Official`、`General`、`Royal`，其餘空字串）、`a_realm`（修士境界 0..8，非修士 −1；渡劫與突破以 `n` 為準，介面端取新境界減一）；模板欄位 `a`、`b`（人名）、`f`、`g`（勢力名；`SectSplit` 的 `f` 為原門派、`g` 為新門派）、`p`、`q`（州郡名；`q` 為遊歷目的地、避難州或相連的另一州）、`x`（代號字串）、`n`、`m`（整數）。`x`／`n`／`m` 的意義依事件：Died 死因／享年／—；Breakthrough —／境界／—；Tribulation 結果（`Passed`、`ShedBody`、`Perished`）／新境界／—；Thread* 宿緣種類／轉世次數／—；Judged 去向／—／—；Traveled `Out`／`Back`；ComeOfAge、FellToDemon 職分；BookEntry 條目；SectWar 洞天名；Famine —／死亡數；NodeShifted 洞天名／新等級／舊等級；SeatMoved 新治所名；ProvinceLost —／溺斃數；LandLinked `Joined`／`Parted`。世界大事（`WorldChanged`）另有 `change`（大事代號）與 `era`（它開啟的紀元名，沒改元為空字串）。只由 `SimHost` 呼叫：每次推進後取走，世界大事以 `world_changed(change, era)` 訊號發出，每一則事件（含世界大事）另以 `event_posted(event)` 訊號發出；開天與接手世界時先取走丟掉，開局前的歷史與讀檔重播的事件不當新消息；傳聞簽（`hud/code/rumor_slip.gd`）接 `event_posted`，一句話由 `locale/code/event_text.gd` 依 7.2 模板組出，點擊飛往走 `MapCamera.look_at_map`，「看人物」與統計名單的一行走 `Hud.open_person` |
| `climate()` | `Dictionary` | 寒暖與靈潮（2.8）：`warmth`、`tide` 與下一世結算後的 `warmth_next`、`tide_next`；所在時期 `climate`、`aura`；靈潮的範圍與進入各時期的門檻 |

高度場的細化在橋接 crate 的 `relief` 模組，其餘貼圖與網格的換算在 `mapbake` 模組；兩者與引擎無關，以 `cargo test -p siming-gdext` 測試；它只讀世界資料，不改變世界狀態。

橋接的擴充規則：

- 一個方法只做一件事，回傳 Godot 內建型別；大量資料用 `Packed*Array`，不逐格跨界呼叫。
- 橋接不含規則，也不快取模擬狀態；每次呼叫都讀當下的 `World`。例外是呈現用的烘焙結果（高度場、河流網格、靈氣與州郡 ID 貼圖）：算一次要幾十毫秒到幾秒，由橋接保存，依下節的時機換新。

### 天地演變的換圖（2.8「畫面」）

- `step()` 跨過一世的結算後，橋接複製當下的地理資料，開一條背景執行緒重算一批呈現資料：靈氣與州郡 ID 貼圖每次都算；水陸與河道的指紋（FNV-1a）和目前高度場依據的不同時，連高度場、高度貼圖（半精度與多級縮圖）、河流網格與水域名（7.3）一起算。
- 算好之前，所有查詢回傳舊的一整套（高度、貼圖、河流、`terrain_height_at`），畫面與選取一致。`poll_terrain()` 取到結果時一起換上，`map_revision` 加一，含高度場時 `terrain_revision` 也加一。還沒換上就又過了一世，舊的一批作廢，只留最新的。
- `TerrainMap` 每幀呼叫 `poll_terrain()`；`map_revision` 變了就換靈氣、州郡 ID 貼圖、州郡淡彩與靈脈線，`terrain_revision` 也變了再換高度、湖面、底色、覆蓋四張貼圖與河流網格，然後發出 `refreshed(terrain)`。地形網格與材質沿用。介面在下一幀重讀標籤、洞天福地、治所與州郡卡。
- 實測（中型世界 384×192 格，高度貼圖 3072×1536）：背景重算一批 2.5–3.5 秒；換上的那一幀主執行緒花 16–23 ms（上傳貼圖與重建河流、靈脈網格）。開天後每一世水陸都有變動，所以每世重算一次高度場。
- 漸變：高度場換上時，`TerrainMap` 把原本的四張貼圖留在材質的 `*_prev_tex`，`terrain_blend` 在 3 秒內由 0 走到 1（`TERRAIN_FADE_SECONDS`，緩入緩出，照實際時間走，暫停時也走完）。著色器在取樣時就把高度、湖面、底色、覆蓋的新舊兩張內插，頂點高度也一樣，所以海岸線與雪線是移過去的，不是兩張畫面疊化。海平面、最高點與星球視角的最高高度三個數值同步內插。舊河流網格留在 `RiverOld0–2` 淡出，新的淡入（`river_line.gdshader` 的 `fade`）。走完後 `*_prev_tex` 指回新貼圖，舊河流收起。漸變還沒走完又換上一批時，沒走完的部分直接到位，從新的一批重新開始；最高速一世 9 秒，正常不會碰到。州界、靈氣、靈脈線、標籤與治所不漸變，換上那一幀就是新的。
- 漸變的成本（中型世界、1920×1080、遠景）：GPU 算繪平時 2.04 ms，漸變中 2.28 ms。
- 讀檔與開天在 `adopt` 裡同步算好整套，結果與背景重算的逐位元組相同（`test_gdd_2_8_rebaked_terrain_equals_the_one_built_on_load`）。
- 其餘場域的烘焙方法在實作對應功能時加入本表，先改本節再改程式。

### 命簿卡片

- `LedgerCard`（`hud`）是命簿卡片的共同底：紙面外框、左側名條、關閉鈕與頁尾動作印、展開收起與 `suspend()`（藏起但不發 `closed`，地圖選取保留）。`ProvinceCard` 與 `PersonCard` 繼承它。卡高以 `max_height` 為上限，`Hud` 設為印匣上緣之上。
- `LedgerList`、`LedgerText`（`ui_kit`）：可捲動清單與帶連結的段落排版。清單內容由呼叫端的 painter 以內容座標作畫、finder 回答點到什麼；滾輪捲動，搖桿模式才開游標貼邊自動捲動。連結以字串在段落裡的位置命中，點到發出 `activated(target)`。
- `Hud` 一次只開一張命簿卡，換卡時把前一張 `{kind, id}` 推入返回堆疊（上限 8），`Esc`／`B` 彈出返回，關閉鈕清空堆疊。`Hud.open_person(id)` 是公開入口，傳聞簽「看人物」與因果模式點魂光呼叫它。
- 因果模式的橋接：`karma_view(options)` 回傳魂光（`glow_person`、`glow_province`、`glow_pos`、`glow_height`、`glow_karma`）與線（`line_thread`、`line_kind`〔0 殺業、1 恩義、2 情緣、3 師徒、4 怨〕、`line_strength`、`line_from`、`line_to`、`line_from_height`、`line_to_height`、`line_debtor`、`line_creditor`、`line_dead`〔0 兩端在世、1 欠債方不在世、2 債主不在世〕、`line_woven`）及 `qualified_lines`、`total_glows`；選項 `all`、`min_strength`（預設 30）、`max_lines`、`max_souls`。`karma_threads(ids)` 回傳指定宿緣的線；`karma_focus(person)` 回傳該人的線與前世所在地點；`karma_between(people)` 回傳兩端都在這組人裡的未了宿緣編號（事件卡溯因視圖用）。純 Rust 部分在 `crates/gdext/src/karma.rs`（不碰 Godot 型別，可直接 `cargo test`）。`KarmaLayer`（`game/modules/map/code/karma_layer.gd`）把它們寫進兩個 MultiMesh（線、魂光）各三份東西副本；`TerrainMap` 公開 `highlight_karma`、`select_karma_soul`、`clear_karma_highlight`、`refresh_karma`、`karma_soul_at`。
- 傳聞簽全螢幕（`RumorSlip.expanded`）時由 `Hud` 統籌：`fullscreen_changed` 訊號觸發暫停模擬（記下展開前的暫停狀態，收合時還原；器物重建不重記）並設 `MapCamera.modal`（平移、縮放、旋轉、選取暫停，搖桿游標與 LT、RT 照常）；`open_person`、`open_event`、`open_province`、`open_menu` 先把它收合。時間與地圖的快捷鍵在全螢幕時由 `Hud._unhandled_input` 擋下，只收 `T`、`Esc`／B 與 Start。
- 天下冊（`Almanac`，5.10）的全螢幕與傳聞簽同一套：`Hud` 以 `fullscreen_changed` 暫停模擬（另記一份展開前的暫停狀態與速度）並設 `MapCamera.modal`；與傳聞簽互斥——一張展開時先收另一張，行止先還原再重記；`open_person`、`open_event`、`open_province`、`open_menu` 也先收合它。`B` 展開與收合，頁籤停在上次的一頁（`Hud` 在器物重建時帶到新的天下冊）。資料在展開那一刻讀一次，之後不變；兩欄是 `LedgerList`，圖的畫法在 `AlmanacPen`（量與畫同一個函式，傳入 `null` 只量不畫）。
- 橋接唯讀查詢 `person(id)`、`person_history(id)`（舊到新，欄位與傳聞簽相同，可直接交給 `EventText`）、`people_in(province)`。歷程的欄位與 `drain_events()` 共用 `event_fields` 組出（`drain_events` 再加地點、身分等自己的欄位；歷程不帶身分欄位：人物卡的歷程省略主角的身分前綴，他人只留姓名，由 `EventText.history_line` 組句）。身分一行由 `locale` 的 `PersonText` 組。
- 宗門卡（`hud/code/sect_card.gd`，繼承 `LedgerCard`，版面見 5.8）。橋接新增在 `gdext/src/sect_api.rs`（`#[godot_api(secondary)]`，不動 `lib.rs` 的主體）：`sect(id)`（宗門卡全部欄位：名稱、正邪、所在州郡與座標、掌門與境界、聲望、立派與覆滅年與紀元、覆滅原因、靈脈節點與範圍、各境界人數、友好與敵對前五名、飛升人數與可考名錄、門人名單；不存在回空字典）與 `sect_history(id)`（門史事件，由舊到新，欄位同 `event`）。事件字典多宗門編號 `f_power`、`g_power`、`a_power_id`，`people_in` 與 `person` 的歷程也帶，由 `event_fields`／`event_record` 補。沒有改模擬規則，也沒有新事件。`Hud.open_sect(id, fly)` 開卡（返回堆疊的項目種類 `sect`）；`PersonCard`、`EventCard`、`RumorSlip`、`Almanac`、`MapOverlay` 各有 `sect_requested(id)` 訊號接它。`GameCursor.extra_hot` 讓沒有控制項蓋住時，地圖山門也顯示可點游標。
- 橋接唯讀查詢 `person_chronicle(id)`（5.12）回傳生平事實清單，由舊到新：先是上一世摘要一筆（`kind` 為 `past_life`，有前世者才有），其後每筆是本世的一件事。欄位見下表；句型與文字由 Godot 端組。

| 欄位 | 內容 |
|---|---|
| `id`、`tick`、`era`／`year`／`month` | 事件編號（整份清單不重複，喪偶取配偶死亡事件）、日、當時的紀元名與年月 |
| `kind`、`role` | 種類代碼；本人的角色，沒有方向為 `self` |
| `other`／`other_name` | 對方的人物編號與事件當時的名字 |
| `other_bond`／`other_bond_name` | 對方在結緣當時另有不同名字（轉世）時的稱呼，否則 -1、空字串 |
| `province`／`province_name`、`power`／`power_name`、`power_from`／`power_from_name`、`target`／`target_name` | 地點、宗門、分宗的原宗門、遊歷目的地 |
| `why`、`detail`、`n`、`thread` | 成因代碼；依種類的代碼（身分、死因、六道、天劫結果、遊歷 `back`／`out`）；境界、享年、世數；宿緣種類 |
| `end_reason` | 結束的原因：`spouse_died`、`master_died`、`master_left`、`disciple_left` |
| `group` | 同組各筆應合成一句；獨立的事等於自己的 `id` |
| `because` | 宿緣後果（將遇、了結、世仇、緣散）才有：`event`、`tick`、`era`／`year`／`month`、`me`／`me_name`、`other`／`other_name`（結緣當時雙方的稱呼）、`thread`、`lives` |

`kind` 代碼：`come_of_age`、`sect_joined`、`sect_left`、`apprenticed`（`role` 為 `disciple`／`master`）、`mentor_ended`、`married`（`role` 為 `spouse`）、`widowed`、`killed`（`killer`；被殺者一側併入 `died`，對方為兇手）、`died`、`ascended`、`judged`、`thread_created`、`thread_omen`、`thread_resolved`、`feud_escalated`、`thread_faded`、`traveled`、`breakthrough`、`tribulation`、`tribulation_omen`、`fell_to_demon`、`sect_founded`、`sect_split`、`succeeded`、`throne_succeeded`、`dynasty_founded`、`rebellion`、`secession`、`usurpation`、`fengshan`。宿緣的 `role`：殺業 `killer`／`victim`、恩義 `beneficiary`／`benefactor`、情緣 `lover`、師徒 `disciple`／`master`、怨 `offender`／`offended`。`sect_joined` 的 `why`：`rogue_joined`（散修投靠）、`followed_master`（隨師遷入）、`recruited`（未入道者後來被宗門收錄，由第二次入道推得）。

- 事件卡（`hud/code/event_card.gd`，繼承 `LedgerCard`）。橋接唯讀查詢：`event(id)`（欄位同 `drain_events` 的每筆，主角身分取人物現況；事件已修剪或不存在回空字典）、`event_causes(id, depth)`（因樹，先根順序攤平；每筆是 `event` 的欄位再加 `level`＝1 為直接因、`parent`＝上一層節點在陣列中的位置，直接因為 −1；每個節點至多 4 個因，同一事件只出現一次；事件不存在回空陣列）、`event_ripple(id)`（後續事件數，沿反向索引往下，上限 300）、`event_ripples(id)`（那些後續事件，由舊到新），以及 `person(id)` 的 `last_event`（最近事件編號，無為 −1）。`drain_events` 與 `event` 共用 `event_record` 組欄位。`Hud.open_event(id)` 開卡（返回堆疊的項目種類 `event`）、`Hud.trace_selected_person()` 是 `X`（輸入動作 `card_trace`，只綁鍵盤）；`RumorSlip.trace_requested` 與 `PersonCard.event_requested` 都接 `open_event`。
- 導演模式（5.13）：決策在 `input/code/director.gd`（`Director`），不碰引擎時間，外部每幀餵真實秒與事件，測試用假時間推進；演出長度查群組 `event_stage` 的節點（`remaining_seconds`、`hold`、`release`）。`DirectorSpeed`（同目錄）管大事自動放慢與恢復。接線在 `hud/code/director_rig.gd`（`DirectorRig`，`Hud` 建立且器物重建時保留）：聽 `SimHost.event_posted`（重要度 2 以上、有州郡的事件計分）與 `MapCamera.player_acted`，每幀依設定與 `Hud` 的忙碌判斷（卡片、天下冊、傳聞簽、選單開著，或游標正在拖曳）餵給 `Director`；字卡是 `hud/code/director_card.gd`，名字連結沿用 `EventCard.links_of` 與 `LedgerText`。設定項在 `GameSettings`（`director`、`director_pace`、`director_idle`、`director_slow`、`director_card`、`director_reduce`），設定頁（`MenuDeck`）有一組「導演」。測試執行器把 `GameSettings.default_overrides["director"]` 設為 false，既有流程測試的鏡頭不會自己動；導演的測試（`test_director.gd`、`journeys/test_director_journey.gd`）自己打開。

## 模擬驅動

- 每幀預算：
  - `SimHost` 依速度計算本幀應推進的 tick 數 `n`。
  - 呼叫 `step()` 直到完成 `n` 次或用掉 8 ms。
  - 未完成者累積到下一幀，累積上限 60 tick，超過即自動降速並提示。
- 指令：介面產生的 `Command` 先放入佇列，在下一次 `step()` 前送入；同時寫入存檔的指令紀錄。
- 背景執行緒（若最高速 20× 跟不上）：
  - `Sim` 放在橋接內的獨立執行緒。
  - 每 N tick 送出一份輕量的「可視快照」（州郡顏色、物件位置、事件）。
  - 模擬本身仍單執行緒，確定性不受影響。

## 可視同步

- **州郡顏色**：地圖模式依賴的資料變動時，重算 `province_color` 查表（256 個顏色），更新貼圖。
- **物件**：以 `PowerId` 或 `ArmyId` 對應 `MultiMesh` 的實例索引；模擬端回報新增、移除、狀態變化，只更新髒的實例。
- **軍隊位置**：每幀依 `progress` 內插。

## 地圖材質

- 地形以 `ShaderMaterial` 加 Godot 著色語言實作 5.3 的著色流程；河流與靈脈共用另一個把帶狀網格依螢幕像素展開的線著色器。
- 鏡頭每幀把高度縮放、古地圖化權重、星球過渡權重與球面變換交給地圖，地圖再設到材質上；地圖模式切換時換 `province_color` 查表與疊色不透明度。
- 貼圖清單與內容見 5.3「貼圖」。水面的雜訊貼圖由 `TerrainMap.water_texture()` 以 `FastNoiseLite` 產生一次，所有地圖共用；水面的流動讀著色器的 `TIME`，與模擬的暫停無關。

## 地理細格（決策 #35）

模擬輸出兩層格點：遊戲格 `World::geo`（州郡、靈脈、場域）與細格 `World::fine`（`FineGeography`，每軸 2 倍）。地形的高度場、湖面與植被底色由細格烘焙（5.3「高度場」）；沒有細格的手工世界退回遊戲格：

- `fine.scale`（= 2；0 表示開發用的手工世界，無細格，退回 `geo`）、`fine.w`、`fine.h`；細格 `(X, Y)` 屬遊戲格 `(X / scale, Y / scale)`。
- `fine.height`（u16，0..65535 ↔ 0..1，填窪後）：高度圖貼圖、山體陰影（光自西北）、海岸線（與 `fine.sea_level` 比較）、海深。
- `fine.terrain`：生態區底色；`fine.temperature`、`fine.moisture`（u8）：生態區之間的漸層（依溫度×濕度混色，不用硬邊）。
- `fine.river`（等級）、`fine.flow`（流量對數刻度 0..255）：墨線河流，線寬依 `flow`。
- 州郡、靈脈、節點、治所仍以遊戲格座標；格心換算為細格 `(x·scale + scale/2, y·scale + scale/2)`。
- 細格陣列只讀；`siming-cli gen --layer atlas` 為同一契約的參考實作（`native/sim/rust/crates/cli/src/render.rs`）。

## 選取

- 由鏡頭射線與地形高度圖求交，得到格點 → 州郡。
- 建築、軍隊以螢幕空間距離挑選，優先於州郡。

## 介面繪製

- 面板與卡片是 `Control` 場景；紙紋、印章、毛邊等器物外觀以 `CanvasItem` 的 `_draw` 向量繪製（5.7、8.8），不使用 Godot 預設主題的外觀。
- 地圖標籤在螢幕空間的 `Control` 層繪製：把標籤的世界座標投影到螢幕後寫字（5.3）。
- 搖桿與鍵鼠都對應到 `InputMap` 的動作；介面與鏡頭只讀動作，不讀實體按鍵（5.9）。
