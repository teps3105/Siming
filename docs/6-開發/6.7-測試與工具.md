# 6.7 測試與工具

模擬規則以 Rust 測試驗證，Godot 端以編輯器內測試與實機畫面驗證，文件與資料另有兩支規範檢查腳本。本節列出各類測試的位置與執行方式，以及無頭工具 `siming-cli` 的子命令。

## Rust 測試

在 `native/sim/rust/` 執行 `cargo test --workspace`。

| 類別 | 內容 | 位置 |
|---|---|---|
| 單元 | 公式（天劫存活率、六道判定、天命變化…）對照 7.1 | `crates/sim/src/**` |
| 世界生成 | 10 個種子都通過 2.2 品質檢查 | `crates/sim/tests/worldgen.rs` |
| 確定性 | 同種子跑兩次 1 運，雜湊相同 | `crates/sim/tests/determinism.rs` |
| 存檔 | 跑半運 → 存檔 → 載入 → 跑到一運，雜湊等於不中斷直跑 | `crates/sim/tests/save.rs` |
| 指令 | 每種權能各下一次，重播雜湊相同 | `crates/sim/tests/determinism.rs` |
| 跨平台 | Windows 與 Linux 跑同一劇本，雜湊相同 | 持續整合（6.6） |
| 平衡迴歸 | 3 個種子各 3 運的統計落在 7.1「平衡目標」範圍內 | `crates/sim/tests/balance.rs`（`#[ignore]`，以 `cargo test -- --ignored` 執行） |

## Godot 測試

Godot 端的測試由專案自己的測試架構執行（`game/tests/harness/`），不用編輯器插件的測試執行器：流程測試要跨幀等待，插件的執行器不等待協程。

```
python tools/tests/run.py                      # 全部套件
python tools/tests/run.py --suite map_journey  # 只跑一個套件
python tools/tests/run.py --case globe         # 只跑名稱含 globe 的案例
python tools/tests/run.py --timeout 300        # 超過秒數就結束 Godot，結束碼 124（預設 900）
```

入口腳本以無視窗模式啟動 Godot，找出 `game/tests/` 底下全部 `test_*.gd` 逐案執行，最後一行印出「測試：N 個套件 M 項，通過 …，失敗 …，載入失敗 …」，結束碼 0 表示全過。執行前先建置橋接程式庫（6.6）。

| 套件 | 位置 | 內容 |
|---|---|---|
| `map_view` | `game/tests/test_map_view.gd` | 鏡頭高度決定的畫面參數：俯角、古地圖化、河流分級、焦點範圍、星球求交 |
| `sim_bridge` | `game/tests/test_sim_bridge.gd` | 橋接回傳的尺寸與內容：網格、貼圖、河流、州郡、標籤、寒暖與靈潮的讀數、世界大事的事件，宗門清單與三教著色表，以及同種子的雜湊 |
| `cultivator_figure` | `game/tests/test_cultivator_figure.gd` | 演算法畫的人物（9.1 封面）：身分決定的特徵、女子的裙與披帛與髮、各身分各姿勢與御劍者任何種子的多邊形都畫得出來 |
| `scene_framing` | `game/tests/test_scene_framing.gd` | 封面取景：焦點的選法與由近到遠的山稜剖面 |
| `storage` | `game/tests/test_storage.gd` | 手動欄位與自動存檔的寫入、排序與淘汰，分享碼的編碼與損壞時的回應，設定檔的讀寫 |
| `map_journey` | `game/tests/journeys/test_map_journey.gd` | 流程：開機、時間控制、鍵盤與滑鼠操作地圖、點選州郡與州郡卡、器物點擊不漏到地圖、搖桿全套操作、星球視角、山門數與宗門數一致、三教模式的範圍圈與圖例出現與消失 |
| `opening_journey` | `game/tests/journeys/test_opening_journey.gd` | 流程：開場運鏡 |
| `hud_layout` | `game/tests/journeys/test_hud_layout.gd` | 器物的位置、大小與實體鍵圖像；介面字串在字型裡都有字；天時儀的兩道弧、停留說明與大事告示 |
| `menu_journey` | `game/tests/journeys/test_menu_journey.gd` | 流程：標題畫面的主選單、開新世界、繼續與設定；鍵鼠與搖桿各走一遍。封面的版面：山影橫貫整個畫面、霧是整幅一片、石台三人其餘散在山水、製作群頁的列 |
| `pause_menu_journey` | `game/tests/journeys/test_pause_menu_journey.gd` | 流程：遊戲中選單的開關與時間行止、存檔與讀檔、分享碼、介面縮放、自動存檔、邊緣捲動 |
| `guide_journey` | `game/tests/journeys/test_guide_journey.gd` | 流程：引導簽六句依序前進、進度保存、設定頁重看 |

判決規則：

- `test_` 開頭的方法就是案例，可以是協程；執行程式一律等待它跑完。
- 斷言失敗、案例期間出現沒有事先宣告的錯誤（腳本錯誤、`push_error`、引擎錯誤）、一個斷言都沒有、套件載入失敗、沒有執行任何案例，都算失敗。
- 流程測試以 `boot()` 開起遊戲場景（小尺寸世界、畫面 1920×1080、時間暫停、不自動存檔、不顯示引導簽），輸入一律以 `Input.parse_input_event` 送進引擎的輸入分派，與玩家操作走同一條路；案例結束時釋放場景並放開所有動作。
- 測試不讀寫玩家的存檔與設定：每個案例開始前把存檔資料夾與設定檔指到 `user://test_run/`，結束後指回原處；要驗存檔內容的套件各用自己的資料夾（如 `user://test_menu/`），並在案例前後清空。
- 新增或改寫套件時做反向驗證：在產品程式注入一個真實缺陷，確認相關案例轉紅後還原。

流程測試驗的是鏡頭、模擬與介面的狀態，不驗像素；畫面要另外擷取、對照 5.7 檢查表判定。無視窗模式不經過顯示卡，著色器的錯誤也只在實機出現。

### 檢查表的截圖

```
python tools/tests/shots.py                           # 存到 .shiftblame/tmp/shots/
python tools/tests/shots.py --out 資料夾 --position 2600,40
```

開一個 Godot 視窗（靜音）執行 `game/tests/harness/shots.gd`，在 5.7 檢查表要求的三種畫面下——1920×1080 鍵鼠（檔名字首 `kb-`）、1920×1080 搖桿（`pad-`）、1280×800 搖桿（`deck-`）——把遊玩畫面、州郡卡、遊戲中選單各頁與標題畫面各頁各存一張 PNG，共 33 張。`--position` 是視窗左上角的實體像素座標，預設落在主螢幕右邊的第二個螢幕。存檔與設定同樣寫在測試用的資料夾。新增介面畫面時，在 `shots.gd` 加上那一頁。

`shots.py` 超過 `--timeout` 秒（預設 600）還沒拍完就結束 Godot。

### 人物放大圖

```
python tools/tests/figure_zoom.py --out 圖.png --given '{"age":1,"wealth":1}' --vary sex:0,1 --focus body --seed 21
```

開一個 Godot 視窗執行 `game/tests/harness/figure_zoom.gd`，把同一個種子、只差 `--vary` 那一項的幾個人並排畫成一張 PNG，用來讀圖比對身分之間看不看得出差別。`--given` 是指定的特徵（JSON），`--focus` 選取景（`body` 全身），`--timeout` 預設 120 秒。`game/tests/harness/figure_probe.gd` 列出哪個身分、姿勢的哪個部位多邊形畫不出來。

橋接的換算另有 Rust 測試（`cargo test -p siming-gdext`）。

## 標題的標誌圖

```
python tools/title/build_logo.py                 # 重做 sources/title/ 的來源與 game/app/assets/title_logo.png
python tools/title/build_logo.py --preview 圖.png  # 另存一張墊底色的預覽圖
```

從素材庫的行書字型（8.10）取「司業命縁」四字的輪廓，交給 VectorCraft 排成一行：墨字一層、朱印一層，墨字帶紙色外暈。需要 fontTools、VectorCraft CLI 與素材庫的字型壓縮檔（`--font` 可另指）。輸出：

| 檔案 | 內容 |
|---|---|
| `sources/title/logo-skeleton.svg` | 程式寫出的輪廓，VectorCraft 的輸入 |
| `sources/title/logo.vectorcraft`、`logo.svg`、`logo.psd` | 可編輯來源 |
| `game/app/assets/title_logo.png` | 遊戲用的貼圖，一個版面單位 4 像素；匯入設定開 mipmap |

字的大小節奏與朱印位置是程式裡的 `LAYOUT` 與版面常數，版面常數與 `game/app/code/title_logo.gd` 對應，改一邊要改另一邊。結構參照的出處記在 `sources/title/參照出處.md`。

## siming-cli

| 子命令 | 功能 |
|---|---|
| `gen --seed S [--size s\|m\|l] --out map.png` | 生成世界並匯出圖檔：地形、河流、州郡邊界、洞天、地名；不需 GPU |
| `gen --seed S --layer province\|aura\|karma` | 匯出指定圖層 |
| `sim --seed S --yun N [--report r.json]` | 無頭跑 N 運；印出每世的統計（人口、勢力數、有名之人數、境界分布、宿緣建立與了結數、超脫數、天書觸發） |
| `evolve --seed S [--yun N] [--era ancient\|middle\|decline]` | 無頭跑 N 運（預設 3）：印開局前的紀元年表與開局日期，每世一行慢變量（寒暖、海平面偏移、靈潮）與當時的紀元，最後列出開局後的改元（2.8） |
| `evolve --seed S --seeds K` | 自 S 起連續 K 個種子只算慢變量與紀元年表（不生成世界），印慢變量的極值、開局後改元次數、紀元長度、開局是紀元第幾年的分佈，以及各類紀元的比例 |
| `replay FILE` | 重播存檔或分享碼並驗證雜湊 |
| `chronicle FILE --min-importance 4` | 印出因果帳（除錯用，不是產品功能） |

## 遊戲內除錯面板（F12）

只在除錯建置出現。

- 每 tick 耗時（各系統分項）、幀時間、實體與事件數。
- 強制事件：指定人物立即突破、指定王朝天命設值、立即量劫。
- 強制事件同樣寫入指令紀錄（標記為除錯），使重播仍可重現。
- 除錯指令不可出現在正式分享碼中。

## 規範檢查腳本（`tools/checks/`，僅用標準函式庫）

| 腳本 | 檢查內容 | 結束碼 |
|---|---|---|
| `python tools/checks/check_hant.py` | 文件（`docs/**/*.md`）、資料與字串（`native/sim/rust/crates/**/data/*.json`、`game/modules/locale/resources/*.json`）、Rust 字串常值與註解中的簡體字；每筆印出「檔案:行:欄: 簡→繁」 | 有簡體字為 1，否則 0 |
| `python tools/checks/check_trace.py` | (a) `params.rs` 每個 `pub const` 的文件註解須引用 7.1 內的代號（反引號）；7.1 中世界生成範圍的列須有常數採用。(b) `docs/` 內相對 Markdown 連結皆可解析。(c) `docs/` 內每個檔案皆被 `docs/索引.md` 連結 | 有問題為 1，否則 0；`--list-info` 另列尚未抄寫的代號 |
| `python tools/checks/check_palette.py` | 5.1 色票在一般視覺與紅、綠、藍黃三種色盲模擬下的最小色差，分組列出最接近的一對；紙面文字色對 paper-light 的 WCAG 對比須達 4.5；色值不在 5.1 內視為腳本與文件不同步 | 對比不足或不同步為 1，否則 0 |

- 簡體對照表僅收錄簡繁字形不同、且簡體字不是常用繁體字的字；刻意保留的簡體文字（例如說明簡體譯名的表格）登記於 `check_hant.py` 的 `ALLOW`。
- `check_hant.py` 與 `check_trace.py` 預設以所在的 repo 為根目錄；需要時加 `--root <路徑>` 指定。
- 在 Windows 終端機執行時先設 `PYTHONIOENCODING=utf-8`，否則輸出含「↔」會因終端機編碼失敗。
