# 6.7 測試與工具

模擬規則以 Rust 測試驗證，Godot 端以編輯器內測試與實機畫面驗證，文件與資料另有兩支規範檢查腳本。本節列出各類測試的位置與執行方式，以及無頭工具 `siming-cli` 的子命令。

## Rust 測試

在 `native/sim/rust/` 執行 `cargo test --workspace`。

| 類別 | 內容 | 位置 |
|---|---|---|
| 單元 | 公式（天劫存活率、六道判定、天命變化…）對照 7.1 | `crates/sim/src/**` |
| 世界生成 | 10 個種子都通過 2.2 品質檢查 | `crates/sim/tests/worldgen.rs` |
| 確定性 | 同種子跑兩次 1 運，雜湊相同 | `crates/sim/tests/determinism.rs` |
| 存檔 | 跑半運 → 存檔 → 載入 → 跑到一運，雜湊等於不中斷直跑 | `crates/sim/tests/save.rs` |
| 指令 | 每種權能各下一次，重播雜湊相同 | `crates/sim/tests/determinism.rs` |
| 跨平台 | Windows 與 Linux 跑同一劇本，雜湊相同 | 持續整合（6.6） |
| 平衡迴歸 | 3 個種子各 3 運的統計落在 7.1「平衡目標」範圍內 | `crates/sim/tests/balance.rs`（`#[ignore]`，以 `cargo test -- --ignored` 執行） |

## Godot 測試

Godot 端的測試由專案自己的測試架構執行（`game/tests/harness/`），不用編輯器插件的測試執行器：流程測試要跨幀等待，插件的執行器不等待協程。

```
python tools/tests/run.py                      # 全部套件
python tools/tests/run.py --suite map_journey  # 只跑一個套件
python tools/tests/run.py --case globe         # 只跑名稱含 globe 的案例
```

入口腳本以無視窗模式啟動 Godot，找出 `game/tests/` 底下全部 `test_*.gd` 逐案執行，最後一行印出「測試：N 個套件 M 項，通過 …，失敗 …，載入失敗 …」，結束碼 0 表示全過。執行前先建置橋接程式庫（6.6）。

| 套件 | 位置 | 內容 |
|---|---|---|
| `map_view` | `game/tests/test_map_view.gd` | 鏡頭高度決定的畫面參數：俯角、古地圖化、河流分級、焦點範圍、星球求交 |
| `sim_bridge` | `game/tests/test_sim_bridge.gd` | 橋接回傳的尺寸與內容：網格、貼圖、河流、州郡、標籤，以及同種子的雜湊 |
| `map_journey` | `game/tests/journeys/test_map_journey.gd` | 流程：開機、時間控制、鍵盤與滑鼠操作地圖、點選州郡與州郡卡、器物點擊不漏到地圖、搖桿全套操作、星球視角 |

判決規則：

- `test_` 開頭的方法就是案例，可以是協程；執行程式一律等待它跑完。
- 斷言失敗、案例期間出現沒有事先宣告的錯誤（腳本錯誤、`push_error`、引擎錯誤）、一個斷言都沒有、套件載入失敗、沒有執行任何案例，都算失敗。
- 流程測試以 `boot()` 開起入口場景（小尺寸世界、畫面 1920×1080、時間暫停），輸入一律以 `Input.parse_input_event` 送進引擎的輸入分派，與玩家操作走同一條路；案例結束時釋放場景並放開所有動作。
- 新增或改寫套件時做反向驗證：在產品程式注入一個真實缺陷，確認相關案例轉紅後還原。

流程測試驗的是鏡頭、模擬與介面的狀態，不驗像素；畫面仍要從編輯器執行遊戲後擷取遊戲畫面、對照 5.7 檢查表判定。無視窗模式不經過顯示卡，著色器的錯誤也只在實機出現。

橋接的換算另有 Rust 測試（`cargo test -p siming-gdext`）。

## siming-cli

| 子命令 | 功能 |
|---|---|
| `gen --seed S [--size s\|m\|l] --out map.png` | 生成世界並匯出圖檔：地形、河流、州郡邊界、洞天、地名；不需 GPU |
| `gen --seed S --layer province\|aura\|karma` | 匯出指定圖層 |
| `sim --seed S --yun N [--report r.json]` | 無頭跑 N 運；印出每世的統計（人口、勢力數、有名之人數、境界分布、宿緣建立與了結數、超脫數、天書觸發） |
| `replay FILE` | 重播存檔或分享碼並驗證雜湊 |
| `chronicle FILE --min-importance 4` | 印出因果帳（除錯用，不是產品功能） |

## 遊戲內除錯面板（F12）

只在除錯建置出現。

- 每 tick 耗時（各系統分項）、幀時間、實體與事件數。
- 強制事件：指定人物立即突破、指定王朝天命設值、立即量劫。
- 強制事件同樣寫入指令紀錄（標記為除錯），使重播仍可重現。
- 除錯指令不可出現在正式分享碼中。

## 規範檢查腳本（`tools/checks/`，僅用標準函式庫）

| 腳本 | 檢查內容 | 結束碼 |
|---|---|---|
| `python tools/checks/check_hant.py` | 文件（`docs/**/*.md`）、資料與字串（`native/sim/rust/crates/**/data/*.json`、`game/modules/locale/resources/*.json`）、Rust 字串常值與註解中的簡體字；每筆印出「檔案:行:欄: 簡→繁」 | 有簡體字為 1，否則 0 |
| `python tools/checks/check_trace.py` | (a) `params.rs` 每個 `pub const` 的文件註解須引用 7.1 內的代號（反引號）；7.1 中世界生成範圍的列須有常數採用。(b) `docs/` 內相對 Markdown 連結皆可解析。(c) `docs/` 內每個檔案皆被 `docs/索引.md` 連結 | 有問題為 1，否則 0；`--list-info` 另列尚未抄寫的代號 |
| `python tools/checks/check_palette.py` | 5.1 色票在一般視覺與紅、綠、藍黃三種色盲模擬下的最小色差，分組列出最接近的一對；色值不在 5.1 內視為腳本與文件不同步 | 不同步為 1，否則 0 |

- 簡體對照表僅收錄簡繁字形不同、且簡體字不是常用繁體字的字；刻意保留的簡體文字（例如說明簡體譯名的表格）登記於 `check_hant.py` 的 `ALLOW`。
- `check_hant.py` 與 `check_trace.py` 預設以所在的 repo 為根目錄；需要時加 `--root <路徑>` 指定。
- 在 Windows 終端機執行時先設 `PYTHONIOENCODING=utf-8`，否則輸出含「↔」會因終端機編碼失敗。
