# 6.8 效能預算

本節列出世界生成、每月推進、畫面更新、記憶體與存檔大小的上限，以及超標時可用的控制手段；效能驗收以這些數字為準。

基準機：4 核 x86-64、整合顯示晶片、16 GB；中尺寸世界，穩態。

| 項目 | 預算 |
|---|---|
| 世界生成（中） | ≤ 1.5 秒（release；含 2 倍地理解析度的細格步驟，決策 #35） |
| `step()` 一般月 | ≤ 0.3 ms |
| `step()` 年底月（含年度系統） | ≤ 6 ms |
| 20× 速度（最高速） | 每秒 40 tick，即約 3.3 個年度 tick，CPU ≤ 60% 一核 |
| 無頭跑 1 運 | ≤ 15 秒 |
| 幀時間 | ≤ 16.6 ms（60 fps），地形 + 200 個建築 + 30 支軍隊 + 6 個奇觀 |
| 幀時間（Steam Deck，800p） | ≤ 33 ms（30 fps） |
| 記憶體 | 模擬 ≤ 200 MB（10 運後）；GPU ≤ 300 MB |
| 存檔 | 指令紀錄 ≤ 100 KB；快照 ≤ 20 MB |
| 場域季步（6.9） | ≤ 0.02 ms；年步 ≤ 0.05 ms |
| 場域重算鏈（移山、損脈） | ≤ 20 ms（事件時）；滄海桑田全圖重算 ≤ 150 ms |
| 場貼圖烘焙 | ≤ 2 ms／次；每季至多 1 次 |

## 量測紀錄

| 日期 | 項目 | 條件 | 結果 |
|---|---|---|---|
| 2026-10-11 | 幀率 | 開發機、從編輯器執行、1920×1080、中尺寸世界、時間暫停，每個鏡頭位置停留 2.2 秒後讀取 | 遠景 120、中景 86、近景 95 fps；每幀約 720 萬個三角形 |
| 2026-10-11 | 每世結算的 `step()` | 開發機、release、中尺寸世界（73,728 格、22 個洞天福地）、種子 20261011 | 1.4–1.9 ms（含靈氣全圖重算與當月其餘步驟）。距離衰減表在開天時建好，約 90 ms，算在開局的載入裡；不用這份表、每世重算距離時是 60 ms |
| 2026-10-11 | 每世結算的 `step()`（寒暖與海平面接上地形之後） | 開發機、release、中尺寸世界、種子 20261011、自然推演三運共 36 世 | 海岸沒動的世 5–8 ms；海岸有變動的世 35–45 ms，多出來的是陸鄰與海鄰的全圖重算。屬於「滄海桑田全圖重算 ≤ 150 ms」這一級，每 360 個 tick 一次（20× 時約每 9 秒一次）。基準機尚未量測 |

這次量的只有地形、河流與介面骨架，沒有建築、軍隊與奇觀；基準機與 Steam Deck 尚未量測。地形網格是目前最大的負擔，Deck 上若不達標，先把網格分塊並依距離降低密度（5.3）。

## 控制手段

- 因果帳中 importance 1 的事件只保留 100 年（3.3）。
- 已死且無未了宿緣的魂，前世生平只保留摘要。
- 年度系統分攤：個人、宗門、州郡、王朝的年度判定依各自的判定月分攤到十二個月（6.3「判定月」，6.10「#待編號 2026-10-12 年度判定分月」，取代 #22 的不分攤）。年底月只剩補魂、天地演變與修剪。
  - 分攤改變模擬結果；每月都要重做的掃描（逐人、逐宗、逐魂的過濾）使整體耗時高於「年底月一次做完」，一般月預算需以分攤後的平均重新校準。
- 因果模式最多繪製 1,500 條線、4,000 個魂光（5.4）。因果線一條一個 MultiMesh 實例、貝茲弧與線寬由頂點著色器算，每幀 CPU 只多幾個 uniform；橋接 `karma_view` 在進入因果模式與每月推進後各取一次。
  - 實測（開發機、release、中尺寸世界、種子 20261011、推進 36 個月、1920×1080、在世 3,122 人）：`karma_view` 一次 3.4 ms（含轉成字典），因果模式下取一次加寫入緩衝 5.0 ms；魂光 3,122（上限 4,000）、線 792（符合強度門檻者 792，全部 1,096；上限 1,500）。每幀間隔因果 11.1 ms、山河 10.6 ms；渲染 CPU 0.27 ms、GPU 1.14 ms；繪製呼叫 291 對 285。基準機與 Steam Deck 尚未量測。
- 場貼圖只烘焙目前模式的場；速度 ≥ 20× 時改為每年一次（6.9）。
