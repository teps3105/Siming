# 6.9 場域框架

[2.7 場域](../2-世界/2.7-場域.md) 定義世界有哪些維；本節定義它們在 `siming-sim` 與 `siming` 中的統一實作：識別、資料佈局、運算核心、耦合矩陣、更新節奏、確定性、存檔與雜湊、效能預算、渲染取樣、工具與測試。目標是：**新增一維只需加一列規格、一個列舉變體、一組參數，不需新寫傳輸或渲染程式。**

模組：`native/sim/rust/crates/sim/src/field/`（`mod.rs` 識別與規格表、`kernel.rs` 運算子、`derive.rs` 衍生場、`recompute.rs` 重算鏈）；渲染端為 Godot `map` 模組的場域烘焙（6.4）。

## 識別

```rust
/// GDD 2.7 場域識別。順序即雜湊、存檔與工具列舉的順序；只追加、不重排。
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
#[repr(u8)]
pub enum FieldId {
    // 地：基底場（格域）
    Height = 0, Terrain, River, Habitability, Continent,
    // 冥：格域
    AuraCell,
    // 人：州域
    Population, CapMod, Devastation, FaithTao, FaithBuddha, FaithRu, Incense, Owner,
    // 冥：州域
    Aura, KarmaQi, Merit, Righteous,
    // 衍生（不保存）
    Turbid, Bond, KalpaLocal, BeastQi,
}

pub enum FieldDomain { Cell, Province, Ley }
pub enum FieldKind { Scalar, Category, Derived }

/// 規格表的一列（GDD 2.7 的表格在程式中的唯一對應；數值引用 params.rs）。
pub struct FieldSpec {
    pub id: FieldId,
    pub domain: FieldDomain,
    pub kind: FieldKind,
    pub range: (f32, f32),          // 截斷範圍
    pub decay_per_year: f32,        // 0 表示不衰減
    pub diffuse_per_season: f32,    // 0 表示不擴散
    pub drift_per_season: f32,      // 0 表示不順流
    pub ramp: Ramp,                 // 地圖色階（5.4 墨分五色的端點色）
}

pub const FIELD_SPECS: [FieldSpec; FieldId::COUNT] = [ /* 依 2.7 與 7.1 填寫 */ ];
```

- `FieldId` 是「維」在程式、siming-cli 圖層選項、除錯面板、雜湊順序中的唯一名字。
- 向量場（教化）拆成三個標量場，使核心只處理 `f32` 標量；`faith` 的「和 ≤ 1」與等比縮放在靠攏運算子（`relax`）之後由 2.3 的規則處理。

## 資料佈局

場的儲存**不另起一套結構**，仍住在既有型別裡（6.2）；框架只提供統一的讀寫入口。

| 域 | 儲存 | 理由 |
|---|---|---|
| 格 | `Geography` 的 `Vec<f32>`／`Vec<u8>`（SoA，`index = y·W + x`） | 7 萬格，必須連續記憶體；已是現狀 |
| 州 | `Province` 欄位（AoS） | ≤ 180 州，AoS 與 SoA 效能無差；M2 進行中的系統直接讀寫 `Province` 欄位，不必重構 |
| 脈 | `LeyNode.strength`、`LeyEdge.strength`、`Sect.seat_node` | 現狀 |
| 衍生 | 不儲存；`derive::*` 讀取時計算 | 避免快照含可推得的值 |

統一入口（`field/mod.rs`）：

```rust
pub fn get(w: &World, id: FieldId, province: ProvinceId) -> f32;      // 州域與衍生場
pub fn get_cell(w: &World, id: FieldId, cell: u32) -> f32;             // 格域；州域場則回傳所屬州的值
pub fn add(w: &mut World, id: FieldId, province: ProvinceId, delta: f32); // 源與匯：加總後依規格截斷
pub fn gather(w: &World, id: FieldId) -> Vec<f32>;                     // 州域快照，索引 = ProvinceId
pub fn scatter(w: &mut World, id: FieldId, values: &[f32]);            // 截斷後寫回
```

- **所有系統對州域場的寫入都經由 `add`**（戰爭、寺院、書院、權能、饑荒……），使寫入點可用 `grep` 找到、都被截斷在值域內、且在效能分析中可計數。M2 已存在的直接寫入（`p.karma_qi += FAMINE_KARMA`）在 U18 改為 `add`，行為不變。
- 讀取可直接讀 `Province` 欄位或用 `get`；`get` 是衍生場的唯一入口。

## 運算核心

所有傳輸運算子都是「快照 → 計算 → 寫回」：先 `gather`，在快照上算出新值，再 `scatter`。結果與州郡的處理順序無關；同一季內多個場各自獨立。

| 運算子 | 公式（`v` 為快照，`N(i)` 為陸鄰依 ID 升冪，`deg(i) = |N(i)|`） | 守恆 | 用於 |
|---|---|---|---|
| 衰減 `decay(r)` | `v'_i = v_i × (1 − r)` | 否 | 業氣、功德、正氣（每年）；殘破用常數減法 `max(0, v − 0.1)` |
| 擴散 `diffuse(k)` | `out_i = Σ_{j∈N(i)} k · max(0, v_i − v_j) / deg(i)`；`v'_i = v_i − out_i + Σ_{j: i∈N(j)} k · max(0, v_j − v_i) / deg(j)` | 是 | 業氣 8%、功德 4%、正氣 4%（每季）。只流向較低的鄰州，依差值；`k ≤ 1` 時恆非負 |
| 順流 `drift(k)` | `m_i = k · v_i`；`v'_i = v_i − m_i + Σ_{j: downstream(j)=i} m_j`；`downstream(i)` 為無時 `m_i = 0` | 是（入海者除外：下游為海則不移動） | 業氣 4%（每季，`KARMA_DRIFT`） |
| 靠攏 `relax(r, target)` | `v'_i = v_i + r × (target_i − v_i)` | 否 | 教化 5%（每年） |
| 搬移 `migrate` | 2.3 遷徙：以快照決定所有流向，再一併套用 | 是 | 人口（每年） |
| 截斷 `clamp` | 依 `FieldSpec.range` | — | 所有寫回 |
| 門檻 `threshold` | 依 ID 升冪逐州判定，使用 `field` 子流抽樣，產生事件 | — | 濁氣效果（疫病、妖滋生、魔窟） |

每季的場域步（6.3 步驟 6）固定順序：

```
for id in [KarmaQi, Merit, Righteous]:        // FieldId 順序
    v = gather(id)
    if spec.drift > 0:   v = drift(v, spec.drift)      // 先順流
    if spec.diffuse > 0: v = diffuse(v, spec.diffuse)  // 再擴散
    scatter(id, v)                                     // 截斷寫回
```

每年的場域步（6.3 步驟 8）：`decay` 各場 → `threshold`（濁氣）；步驟 7 的人口與教化沿用 2.3 的順序，其中遷徙與靠攏分別是 `migrate`、`relax`。

格域場沒有每季運算子：靜態，只在重算鏈（2.7）觸發時由 `recompute.rs` 重算受影響的格與州。

## 確定性

1. 傳輸只用快照，寫回依 `ProvinceId` 升冪；鄰居列表 `neighbors` 依 ID 升冪（2.2 生成時排序），擴散的加總順序因此固定。
2. 格域重算依 `cell` 升冪；受影響集合以 `BTreeSet<u32>` 收集。
3. 只用 IEEE 754 基本運算與 `exp`（靈氣衰減）；不用 `HashMap` 迭代（6.5）。擴散與順流的係數為常數乘法，不涉及超越函數。
4. 門檻判定用 `field` 子流，依州 ID 升冪抽樣；一州不觸發時**不**抽樣（避免消耗序列改變後續），即「先算機率，機率 > 0 才抽」。
5. 衍生場不保存、不雜湊；它們是純函數。

## 存檔與雜湊

- 快照（6.5 `snapshot`）包含所有保存的場：格域在 `Geography`，州域在 `Province`，脈域在 `LeyNode`、`LeyEdge`。`FieldId` 順序即 `World::hash()` 餵入州域場的順序：對每個 `Province` 依 `FieldId` 順序寫入各欄位的 `to_bits()`；`Geography` 的格域場同樣依 `FieldId` 順序。新增一維時在列舉**末尾**追加，`sim_version` 遞增。
- 重播（6.5）不需要特別處理：場域步沒有隨機，門檻步使用固定子流。

| 場域年步（`decay` + `threshold`） | ≤ 0.05 ms | — |

控制手段：只烘焙目前模式的場；非連續場模式不烘焙；速度 ≥ 20× 時烘焙改為每年一次。

## 渲染取樣

同一條著色路徑（5.3 地形著色器步驟 5）處理所有連續場：著色器只讀 `field` 貼圖與 `field_ramp` uniform，不知道場是什麼。

### 烘焙（`field_bake.rs`）

```
依模式選 FieldId
  格域場（aura_cell）：  值 → 以 2.2 格點雙線性放大到 1024×640
  州域場（turbid、bond）：格值 = get(州) → 3×3 盒狀模糊 × FIELD_BLUR 次（x 環繞；海格以 0 參與）→ 雙線性放大
  正規化：(v − range.0) / (range.1 − range.0) → R8
上傳 `field`；設定 `field_ramp`（5 色 + 4 門檻）
```

- 州域場模糊後，州界處的氣場互相滲透，像墨在紙上化開；海格以 0 參與，使氣場在海岸自然淡出。
- 烘焙在 CPU 執行，每季或切換模式時一次，符合預算。

### 墨分五色（5.4）

`field_ramp` 由 `FieldSpec.ramp` 提供：兩個端點色（例如 paper → karma）與五階門檻 `FIELD_INK_LEVELS`（0.1、0.3、0.5、0.7、0.9）。著色器把正規化值量化成焦、濃、重、淡、清五階，階與階之間以 `stroke` 貼圖的筆觸雜訊做 0.05 寬的毛邊，再與地形底色相乘。全部著色器邏輯與場無關。

## 工具

- `siming-cli gen --layer <FieldId>`：匯出任一格域場或州域場（投影後）的灰階 PNG；`sim --layer <FieldId> --every 1yun`：模擬期間定期匯出，供驗收截圖與平衡觀察（例如業氣順流是否在河口聚積）。
- 除錯面板（F12，6.7）：「場域檢視」下拉選任一 `FieldId` 覆蓋在目前模式上；顯示該場的 Σ、最大值與其州郡；本 tick 各場的 `add` 次數。
- `siming-cli sim --report` 新增每世的場統計：各州域場的加權平均與最大值、魔窟數、順流淨移動量。
