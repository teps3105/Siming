# 6.3 推演流程

`Sim::step()` 推進一個月。系統依下列固定順序執行；同一步內依 ID 升冪處理。每步標明使用的隨機子流（6.5）。

## 事件隊列與日（2026-10-13 起）

- 時刻單位是日（`Tick` = 日，每月 30 日、每年 360 日）。下文表中的 `tick` 條件仍以「月序」書寫，換成日序即乘 30；`Sim::step()` 仍推進到下一個月末。
- 個人規則走事件隊列（二元堆，鍵為日與入隊序，取消用惰性作廢）：壽終、入道、遊歷返回算出確切的日；遊歷出發與婚配各以每人的指數等待抽出下一次時刻（年率沿用 `TRAVEL_CHANCE`、`MARRY_CHANCE`，不設「至少隔一年」的下限）；修煉、突破、心魔、獵魔與刺殺、劫兆在每人固定的年內某日結算（由種子與人物編號雜湊決定，1–360 日）。魂的中陰、他道、等待到期同樣入隊。
- `Sim::advance_to(day)` 與 `advance_until(條件)` 依日推進：同一日先做月步進、再處理隊列。月步進仍負責尚未改成隊列的全局系統（人口、靈氣、宗門、州郡、王朝、演變、大劫）。
- 每步成本不隨魂數與年數成長為目標：在世者找人（婚配、獵魔）走依州郡分桶的索引快取（最多隔一個月重建）；宿緣線只留未了者在輪替桶，已了結者從魂的啟用名單移到各魂最多 16 筆的精簡紀錄（`SETTLED_CAP`）。

## 觸發條件

| 名稱 | 條件（`tick` 從 1 起算，開天後第一個月為 1；預跑也推進 tick 1..=120，4.6） |
|---|---|
| 每月 | 每次 |
| 每季 | `tick % 3 == 0` |
| 每年 | `tick % 12 == 0`（年底月，第 12 月）。只有補魂、天地演變、因果帳修剪留在年底月；其餘「每年一次」的判定一律分月，見下節「判定月」 |
| 每世 | `tick % 360 == 0` |
| 劫兆期 | `tick % 4320 > 3960` 或 `tick % 4320 == 0`（每運最後 30 年） |
| 量劫年 | 劫兆期內，且 `tick % 4320 > 4284` 或 `== 0`，並且是每年 |
| 運末 | `tick % 4320 == 0` |

## 判定月

個人、宗門、州郡、王朝的年度判定不再集中在年底月，每個實體有固定的判定月（`schedule::judge_month`：世界種子、類別、編號雜湊後 mod 12，對應曆法 1–12 月），在自己的月份做，事件的 tick 就是真的發生月。同一實體每年恰好輪到一次，各類別分布大致均勻。

| 類別 | 編號 | 在判定月做的事 |
|---|---|---|
| 州郡 | 州郡 ID | 步驟 7：人口成長、饑荒、遷徙、殘破恢復、城池等級；饑荒當月通知所屬王朝（記入滾動 12 個月的饑荒州數）並賑災；無主州郡的立國判定（步驟 19） |
| 有名之人 | 人物 ID | 步驟 11–13：修煉、突破、天劫、心魔、斬妖、襲殺、劫雲預兆、遊歷出發、入道、婚配（發起者）；散修創宗與投靠（步驟 15、16） |
| 魂 | 魂 ID | 步驟 14：宿緣的相遇（由輪到的魂帶出，每魂每年至多一次，以 `World` 的年度戳記跨月記帳）；師徒超越與預兆以債務方的魂為準 |
| 宗門 | 勢力 ID | 步驟 15–18：繼任與分裂、補足、拜師、聲望與範圍、覆滅檢查；爭脈之戰以一對宗門中編號較小者的判定月為準 |
| 王朝 | 王朝 ID | 步驟 19：財政、繼承、國策與詔令、開疆與宣戰、天命、起義與割據、封禪、補缺、王族生育、關係與聲望；新生王朝滿 12 個月後才開始結算 |

- 每月都執行這些步驟，但只處理判定月等於本月的實體；同一個月內各步的相對順序與下表相同。
- 壽終（步驟 10）每月檢查：年齡 = ⌊(tick − 出生月) / 12⌋，人在滿壽元的那個月（出生月）死亡。判定讀到的年齡就是當月的實際年齡，年齡沒有「年底才加一歲」的時點。
- 年度判定的機率與公式仍是年率。新出生或年中才具備資格者（如剛滿 12 歲、剛突破到可遊歷的境界）等到下一個自己的判定月才被判定，最晚一年；判定月先於資格成立的那一年不補判。
- 天命公式的「本年饑荒州數」「本年新得、失去州數」改為過去 12 個月的滾動累計：每筆發生時記入王朝的 `window`（發生 tick、得、失、饑荒），滿 12 個月（`tick + 12 <= 現在`）在該王朝的判定月移出並從累計扣除。
- 分月的 `monthly_*` 函式與一次判定全部的 `yearly_*` 函式並存，後者供測試與工具使用。

## 通則

- 所有對州域場（人口、殘破、業氣、功德、正氣……）的寫入經由 `field::add`（6.9），寫入即截斷在值域內；同一步驟內一個場只由一個系統寫入（6.9 耦合矩陣）。
- 任何步驟中，已死者一律跳過。
- 冷卻與遊歷期間以月數計（例如 3 年 = 36 個月）。
- 步驟 14 的處理順序見 3.3「相遇」。
- 預跑（4.6）期間事件照常寫入因果帳，但不進傳聞、不觸發奇觀、不給天機。

## 隨時觸發的處理

### 死亡（任何步驟中發生時立即執行）

1. 寫入死亡事件（或超脫事件）。
2. 魂：
   - 超脫 → `Liberated`。
   - 否則 → 進入中陰，`until = tick + 2`。
3. 勢力：成員移除；首領死亡時，依勢力種類觸發繼承（宗門、寺院、書院、王朝），在本步驟內完成。
4. 人際：配偶、師徒關係解除（宿緣保留）。
5. 有殺者時：依 3.1 計業，必要時建立殺業線。
6. 進行中的會戰：統帥死亡時，軍隊改由下一位武將統率，沒有則無統帥。

### 出生（步驟 5、12、16 中發生）

1. 依 3.4 建立有名之人（輪迴出生寫入 `Rebirth`；`Born` 只用於新魂與開天，7.2）。
2. 魂的轉世處理：
   - 宿慧與道緣傳承（3.1）。
   - 欠債方利息：殺業線與怨線先 S += 強度 × 0.1（以舊強度），再強度 × 1.1（上限 100）（3.1）。
   - 所有相關線的 `lives` 更新（3.3）。

### 事件寫入

1. 指派 EventId，寫入因果帳。
2. 偵測天書條目，新條目寫入世界天書，首次達成給天機（4.3、4.5；M2 為空操作）。
3. 加入 `pending_events`。

## 事件輸出

- `step()` 產生的事件累積在 `pending_events`。
- 呈現層每幀呼叫 `drain_events()` 取走，用來觸發奇觀與傳聞（6.4）。
