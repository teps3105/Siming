# 4.8 存檔與分享

一局遊戲可以存進欄位、由系統每世自動存一份，也可以變成一段分享碼貼給別人。三者存的是同一份內容：重現這個世界所需的種子、開局設定、指令紀錄與目標時刻（[6.5](../6-開發/6.5-確定性與存檔.md)）。讀回來時由開天重播到那個時刻，再比對世界雜湊。操作入口在標題畫面與遊戲中選單（[9.1](../9-發行/9.1-Steam-Demo範圍.md)）。

## 玩家能做的事

| 動作 | 入口 | 結果 |
|---|---|---|
| 存檔 | 遊戲中選單「存檔」，選 10 欄之一 | 空欄直接寫入；已有存檔的欄先問「蓋過去？」，預設停在取消 |
| 繼續 | 標題畫面「繼續」 | 讀最近存的一份（手動與自動一起比存檔時間）；列上寫著世界名與日期 |
| 載入 | 標題畫面或遊戲中選單「載入」 | 列出有內容的手動欄與自動存檔，各寫世界名、世界裡的日期、存檔的月日時分；選一份即讀 |
| 刪除 | 載入頁停在某一份時按 `Delete`／X | 先問，預設停在取消 |
| 複製分享碼 | 遊戲中選單「分享碼」 | 這個世界此刻的分享碼進剪貼簿 |
| 匯入分享碼 | 標題畫面或遊戲中選單「分享碼」→「從剪貼簿匯入」 | 讀剪貼簿裡的分享碼，換成那個世界 |

沒有任何存檔時，「繼續」與「載入」是不能選的虛線框。

## 自動存檔

時間每跨過一世（360 個月）存一份，只留最新的 5 份，舊的刪掉。自動存檔不佔手動欄位，在載入頁另列一節。

## 讀檔的過程

1. 檢查存檔文字；讀不懂或模擬版本不符時告知原因，原本的世界照舊。
2. 以存檔裡的種子與開局設定重新開天，再重播指令到存檔的時刻。重播分段進行，每幀最多花 12 毫秒，畫面顯示進度條，地圖不更新。
3. 重播到位後比對世界雜湊；相符才把畫面換成讀出來的世界，並維持暫停。

讀檔途中不能返回。失敗時告知原因並回到原本那一頁，原本的世界不受影響。

## 檔案

存檔放在 Godot 的使用者資料夾 `user://saves/`（Windows 為 `%APPDATA%\Godot\app_userdata\司業命緣\saves\`）。一個檔一份存檔，JSON 文字：

| 檔名 | 內容 |
|---|---|
| `slot_00.json` … `slot_09.json` | 手動欄位第一到第十欄 |
| `auto_<tick>_<序號>.json` | 自動存檔 |

| 欄位 | 說明 |
|---|---|
| `format` | 存檔檔案的格式版本，目前為 1 |
| `kind`、`slot` | `manual` 或 `auto`；手動欄位的編號（自動存檔為 -1） |
| `name`、`date`、`tick` | 世界名、世界裡的日期、時刻；列表顯示用，不必解開存檔文字 |
| `saved_at`、`order` | 存檔的現實時間，與同一秒內的先後 |
| `options` | 開局設定（4.6 的七項） |
| `save` | 模擬端的存檔文字（6.5） |

設定另存在 `user://settings.cfg`，不隨存檔走。

## 分享碼的格式

`SMG1-` 加上一段網址安全的 Base64（不補 `=`）。解開後前 4 個位元組是校驗，其餘是 deflate 壓縮過的存檔文字：

```
分享碼 = "SMG1-" + base64url( SHA-256(壓縮後內容)[0..4] + deflate(存檔文字) )
```

- 校驗用來在解壓之前擋下抄錯或被截斷的分享碼。
- 解壓後的大小上限是 16 MB。
- 匯入時的回應：開頭不是 `SMG1-` 為「這不是分享碼」；字元不合、校驗不符或解不開為「分享碼不完整或已損壞」；兩者都不換世界。通過後照「讀檔的過程」進行。

## 版本相容

- 模擬規則一改，重播的結果就不同，所以存檔文字帶有模擬版本號（6.5 的 `sim_version`）。
- 版本不符的存檔與分享碼目前一律拒絕，並告知原因。
- 1.0 之前不保證跨版本相容。
