# 1.4 產品規則

本節是全專案共同遵守的十二條規則，分為設計、工程與文件三類；新增系統、權能或文件前先對照這些規則，違反者不做。

開發一律遵守。

## 設計規則

1. **魂優先**：新系統若不能產生或了結宿緣，先問它為什麼存在。
2. **看不見就不存在**：每個機制都必須有地圖上的表現（線、氣、光、顏色、模型、特效）；只有數值變化的機制不做。
3. **力量必有業**：新增的司命權能必須定義它的業的代價（見 [4.4 天道業障](../4-玩法/4.4-天道業障.md)）。
4. **文字只有一句**：任何事件的文字描述不超過一句（約 30 字），只出現在卡片、傳聞與天書中。

## 工程規則

5. **確定性是硬約束**：相同種子 + 相同指令序列（含 tick）⇒ 位元級相同的世界。見 [6.5 確定性與存檔](../6-開發/6.5-確定性與存檔.md)。
6. **模擬與呈現分離**：模擬核心是純 Rust 函式庫，不依賴遊戲引擎或 IO；畫面只讀取模擬狀態與事件。
7. **Godot 呈現、Rust 規則**：畫面、輸入、儲存由 Godot 專案負責；遊戲規則只寫在 Rust 模擬核心，Godot 端不重寫規則（6.1）。
8. **數值集中**：所有遊戲數值定義在 [7.1 參數總表](../7-附錄/7.1-參數總表.md)，程式中對應 `native/sim/rust/crates/sim/src/params.rs`；章節中的數值是說明，不一致時以 7.1 為準。
9. **效能預算**：見 [6.8 效能預算](../6-開發/6.8-效能預算.md)。

## 文件規則

10. **文件先行**：M0 產出完整 GDD；之後依文件開發。程式與文件不一致時，先改文件再改程式。
11. **GDD 結構**：`docs/索引.md` + `docs/N-章/N.M-節.md`，最多兩層，不建立 N.M.K。
12. **決策只追加**：重大決策記在 [6.10 決策紀錄](../6-開發/6.10-決策紀錄.md)，不刪改既有條目。
