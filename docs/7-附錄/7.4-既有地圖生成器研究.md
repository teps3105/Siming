# 7.4 既有地圖生成器研究

目的：盤點既有的奇幻地圖生成器與世界模擬器，找出可借用的技術，避免重造輪子。對應 [2.2 世界生成](../2-世界/2.2-世界生成.md)、[2.3 州郡與人口](../2-世界/2.3-州郡與人口.md)、[7.3 命名規則](7.3-命名規則.md)。

## 0 研究方法與可信度

- 本節撰寫時沙箱網路只允許部分網域：Red Blob Games、mewo2.com、Here Dragons Abound 的頁面**無法直接取得**。標「已驗證」者，是直接讀過原始碼或頁面；標「記憶」者，來自作者文章或原始碼的既有知識，採用前請再核對原文。
- 已直接讀取：mapgen4 `map.ts` 原始碼、mapgen4 README、Azgaar 維基（Heightmap template editor）、crates.io API（版本與授權）、Civ V/VI 社群對大洲分離的說明。
- 方針（協調者釐清）：板塊、雜訊、模板（blob）、渲染是**可組合的參考方向，不是互斥選項**。本節逐一研究各自的貢獻，3.0 提出分層混合管線；決策 #31 正修訂為混合方案（#32）。
- 本專案現況（讀自 `native/sim/rust/crates/sim/src/worldgen/`）：`height.rs` 目前為「大陸核（高斯丘＋葉）＋ domain warp ＋ 細節 fBm」，山脈用造山雜訊等值線帶 × 脊狀碎形；`climate.rs` 已有三圈風帶逐列掃描與雨影；`hydrology.rs` 為 priority-flood ＋ D8 ＋ 累積量；`provinces.rs` 為宜居度加權 Poisson-disk ＋ 多源 Dijkstra。**注意**：`docs/2-世界/2.2-世界生成.md` 步驟 1 仍寫板塊，與目前程式碼（#31 雜訊版）不一致；待 #32 混合方案定案後一併同步，本節不改。
- 現有問題：雜訊結果常為單一超大陸。

## 1 各專案研究

### 1.1 Azgaar's Fantasy Map Generator

來源：https://github.com/Azgaar/Fantasy-Map-Generator ，維基 https://github.com/Azgaar/Fantasy-Map-Generator/wiki （已驗證模板步驟表：https://github.com/Azgaar/Fantasy-Map-Generator/wiki/Heightmap-template-editor ）。授權 MIT（記憶）。

關鍵技術：
- **網格**：抖動格點 → Delaunay/Voronoi 單元（約 1 萬至 10 萬格），單元記錄高度、鄰接、河流、生物域、國家、文化。
- **高度圖模板**：以一串指令組合地形，每步帶「次數 n、高度範圍 h、x/y 範圍（百分比）」：
  - `Hill` 圓丘（從隨機點向鄰格以遞減係數擴散的 blob）、`Pit` 窪地
  - `Range` 長條山脊（兩點間沿路徑展開，再向兩側遞減）、`Trough` 長條谷
  - `Strait` 以 `d`（方向）`w`（寬，上限地圖寬的三分之一）切出海峽，把陸地一分為二
  - `Mask` 壓低邊緣（或中心）、`Invert` 鏡射、`Add`/`Multiply`（可只作用於陸地或某區間）、`Smooth`
  - 內建模板（如 Continents、Archipelago、Atoll、Peninsula、Pangea、Isthmus 等，名稱記憶）即是上述指令的固定序列，種子只決定隨機落點。
- 流程：高度 → 海岸/特徵（陸地、湖、海的連通分量標號）→ 溫度（由緯度與高度決定：緯度＋高度遞減）→ 降水（風向、沿風逐格扣減）→ 河流（先填窪，再沿下坡累積流量）→ 生物域查表（溫度 × 濕度矩陣）→ 文化 → 城鎮（burg，以適宜度評分）→ 國家（多源擴張，代價含地形、河、海）→ 宗教 → 省份 → 路網。
- **命名**：每個文化綁一個名稱基底（語料詞庫），以 Markov 鏈（按字元，記憶）生成，並以「雙音節長度偏好、避免重複」之類規則過濾。
- 特徵標號（連通分量）與「大洲／島／湖」分類是下游命名與州郡的共同基礎。

可借用：
- **模板化的步驟序列**，尤其 `Strait`（在陸地上切海峽）與 `Mask`；以「步驟序列＋種子」取代單一雜訊公式，結果多樣又可控。
- 溫度 × 濕度的生物域**查表矩陣**（資料驅動，易調）。
- 海岸特徵連通分量標號（本專案 `continent_of` 已有類似）。

不適用：
- 平面地圖、非環繞；Voronoi 單元網格——本專案是等距圓柱格點（W=2H）且需東西環繞，單元網格對 2.5D 水墨渲染、自走模擬沒有必要。
- 國家／文化／宗教系統與本專案的三教勢力設計不同，僅作對照。

### 1.2 Martin O'Leary「Generating fantasy maps」

來源：https://mewo2.com/notes/terrain/ （本次無法連線，內容來自記憶）；程式 https://github.com/mewo2/terrain （MIT，記憶）；名稱產生器 https://github.com/mewo2/naming-language （記憶）。

關鍵技術：
- **起始高度**：隨機斜面、錐形、圓丘疊加，再以 `relax`（Voronoi 鬆弛）與平滑。
- **侵蝕**：串流功率律 `Δz ∝ −k·A^m·slope`（`A` 為流量累積），加上少量土壤蠕移；迭代數次到十數次後，山脊呈樹枝狀、谷地貫通，看起來「像真的」。這是「雜訊地形不像真的」的最有效補救。
- **填窪**後才算流向與河流；河流路徑取流量門檻以上的邊。
- **海岸線**：取等高線並加入小幅碎形抖動；海平面以分位數決定陸地比例（與本專案相同）。
- **城市放置**：以「流量（水源）、平坦、鄰近海」評分，貪心挑選並對周圍降權（與本專案州郡種子相近）。
- **標籤**：城市、地區、山脈標籤用模擬退火／貪心尋找互不重疊、貼近特徵的位置。
- **命名語言**：為每個「語言」隨機生成音素表、音節結構與拼寫規則，產出風格一致的名稱。

可借用：
- **輕量侵蝕**（在格點上以流量累積加深河谷、軟化山脊）：成本低、效果顯著，且可決定性（固定迭代數與處理順序）。
- 標籤放置的「評分＋貪心」思路（見第 7 節）。

不適用：Voronoi 單元；其語言生成偏拼音式音素，不適用漢字地名。

### 1.3 Red Blob Games（Amit Patel）

來源（本次無法連線，內容來自記憶）：
- Polygon Map Generation：http://www-cs-students.stanford.edu/~amitp/game-programming/polygon-map-generation/
- 雜訊轉地形：https://www.redblobgames.com/maps/terrain-from-noise/
- mapgen4：https://www.redblobgames.com/maps/mapgen4/ ，原始碼 https://github.com/redblobgames/mapgen4 （Apache-2.0，已驗證）
- 行星生成實驗：https://www.redblobgames.com/x/1843-planet-generation/
- 距離場與高度控制：https://redblobgames.com/x/1728-elevation-control 、https://www.redblobgames.com/x/1729-generate-details/

**terrain-from-noise 的要點（記憶）**：
- 島嶼遮罩：`e = lerp(e, 1 − d, mix)`，`d` 為到中心的距離（或 `min(1, d_x² + d_y²)`、`1−(1−x²)(1−y²)`）；
- 重分佈：`e = pow(e·k, p)`，p 大則谷地平坦、山峰尖；
- **脊狀雜訊**：`1 − |2n − 1|`，高八度以低八度結果加權（`e += 0.5·e₀·noise₂`），使山脊上有細節、谷地平滑；
- 生物域 = f(高度, 濕度)；用「高度」與「雜訊」分開的兩條獨立雜訊控制濕度。
- 重點結論：用一個**單點／少數點的遮罩**決定「陸地在哪」，再用雜訊決定「形狀」，比單靠雜訊閾值穩定。

**mapgen4（已驗證，讀自 `map.ts`）**：
- 高度：山峰三角形出發做 BFS 距離場（每步 `spacing·(1 + jaggedness·(rand − rand))`），山高 `em = 1 − (16 / 2^sharpness)·distance`；丘陵 `eh` 為兩層雜訊（低振幅，只為讓河流蜿蜒）；以 `weight = e²` 混合 `e = (1−w)·eh + w·em`，使越高越像山脈；海底 `e *= ocean_depth + noise`；海岸雜訊以 `(1−e⁴)` 限縮在海岸附近。→ **山脈 = 到「山脊線」的距離場，而不是雜訊閾值**，這是脊狀山脈最可控的作法。
- 降雨（風模擬）：把單元依風向投影排序，由上風到下風逐一處理；濕度＝上風已處理鄰居的平均；海格蒸發 `evaporation·(−elevation)`；降雨 `raininess·humidity`；若 `humidity > 1 − elevation`（氣流被地形抬升）則多餘部分 `rain_shadow·(humidity − (1−elevation))` 轉為降雨並從下風濕度扣除 → 迎風坡多雨、背風雨影。與本專案 `climate.rs` 的逐列掃描同源但更細：它用**高度連續函數**判定抬升，而我們用「陸高 > 0.62 才扣 0.3」的門檻。
- 河流：先從海向上做 priority-queue 洪填，每格記下「從哪個鄰居被到達」作為下坡指標與拓撲順序；每格流量 `flow·moisture²`；依逆序累加；**把幹流高度壓低到與支流一致**，保證河必下坡。
- 授權 Apache-2.0，可商用。

**行星實驗（記憶）**：球面三角網格＋板塊模擬＋風帶降雨，結論是「球面版的格點更複雜，收益有限」；我們在單位球上取三維雜訊已避開接縫與極區擠壓（2.2 尺寸節），做法正確。

可借用：距離場式山脈、連續的雨影公式、洪填同時產出拓撲順序、幹流壓低保證下坡。
不適用：其動態互動編輯、WebGL 渲染管線。

### 1.4 WorldEngine、Tectonics.js、Undiscovered Worlds

來源（記憶）：WorldEngine https://github.com/Mindwerks/worldengine （MIT）；Tectonics.js https://github.com/davidson16807/tectonics.js ；Undiscovered Worlds https://github.com/Undiscovered-Worlds/ （作者 Rubyfiend/Anon，Python/Java）。

- WorldEngine：板塊雜訊 → 高度 → 侵蝕 → 溫度/降水 → 蒸發/河/湖 → Holdridge 生命帶。重點是「Holdridge 生命帶」查表與流程順序，與我們一致。
- Tectonics.js：真正的板塊運動模擬（碰撞、隱沒、火山），結果最像地球，但完整模擬**慢且不易控制**。可取的是其**結果形態**而非逐步模擬：板塊決定大洲佈局、造山帶位置、島弧與裂谷，這些用「靜態板塊分區＋邊界類型」即可得到，無須跑時間步（2.2 現文件即是此作法）。
- Undiscovered Worlds：多階段（板塊 → 山 → 侵蝕 → 氣候 → 生物）；氣候部分用緯度帶＋大陸性（離海遠近）＋山陰影，是「氣候怎樣才可信」的好參考。

借用（與雜訊疊加，見 3.0）：
- 板塊（球面 Voronoi ＋ 運動向量 ＋ 邊界類型）提供**宏觀結構**：大洲佈局與分離、聚合邊界的造山帶、洋陸聚合的海岸山脈與海溝、洋洋聚合的島弧、張裂的裂谷海。
- 雜訊提供**微觀細節**：海岸碎形、地表起伏、domain warp 讓板塊邊界曲折。
- 兩者互補：只用板塊則邊界過於規則；只用雜訊則無結構保證（目前超大陸的根因）。

### 1.5 Dwarf Fortress 世界生成與歷史模擬

來源（記憶）：https://dwarffortresswiki.org/index.php/World_generation 。

- 地形：多層碎形（高度、降雨、溫度、排水、礦化、邪惡度），**每層獨立種子與碎形**，再由規則決定生物域；海平面以比例決定。
- 侵蝕與河：「隨機走」的河，由高處往海；有人為保證河流入海。
- 歷史：模擬數百年，先放種族，再事件（戰爭、遷徙、建城、神器），結果可生成「史實」。
- 對本專案最有參考價值的是**多層獨立碎形**（不要共用同一雜訊）與「世界生成後再跑歷史」的管線切分；本專案歷史是遊戲內自走模擬，不屬於 worldgen。

### 1.6 WorldBox、Songs of Syx

- WorldBox（神之模擬器）：格點上以規則（相鄰、高度）做生物域與自動邊界，重點是**可玩性優先、規則簡單**；其渲染為像素，不可借。
- Songs of Syx：格點世界地圖，區域由預先製作的圖片與區塊組成；對本專案無技術可借，僅證明「格點地圖 ＋ 區域」可作策略遊戲。（兩者皆記憶，無一手來源；不要依賴。）

### 1.7 CK3 / 三國志 / 信長之野望 的地圖管線

- CK3（記憶，Paradox 公開的 mod 文件，見 https://ck3.paradoxwikis.com/Map_modding ）：以 `heightmap.png`、`provinces.png`（每省獨一無二的 RGB 純色塊）、`rivers.png`（索引色）、`definition.csv`（顏色→省 ID）、`default.map`（海、湖、不可通行省的清單）、`adjacencies.csv`（跨海／河口通道）。**省份是人工繪製的**，不是由高度圖自動生成。
- 啟發：
  1. 省份資料自成一層（ID 圖 ＋ 表），與地形圖分離——本專案 `province: W×H u16` 已同構。
  2. **省份邊界應與自然邊界對齊**（山脊、大河、海岸），玩家讀圖才直觀；CK3 手繪天然做到，我們要用代價函數近似（見 3.5）。
  3. 「鄰接表」要顯式處理海峽／河口通道（渡口），2.3 已有類似設計時可核對。
- 三國志／信長之野望：州（大區域）下分郡／城；地圖以山、河、關隘分割，**關隘與渡口**是戰略要點。可由「山脈格上的最低通過點（鞍部）」自動偵測關隘——值得列入後續。

### 1.8 Civilization / Old World 地圖腳本（大洲分離保證）

來源（社群資料，已驗證到論壇說明層級，未讀原始碼）：https://forums.civfanatics.com/threads/lua-map-script-help.489370/ ；https://forums.civfanatics.com/threads/detailed-worlds.605655/ 。

- 「Continents」腳本在碎形地圖上額外執行**「海洋裂隙」(rift) 步驟**：沿一條線把高度壓低，強制大洲分離；「Fractal」腳本沒有這一步，因此常連成一塊。
- Civ V 的 Pangaea 做法是**驗收與重抽**：若最大陸塊占陸地比例 < 84% 就重新生成；Small Continents 反過來限制最大陸塊 < 33%。
- 啟發：**「生成 → 量測連通分量 → 不合格就換子種子重抽或補救」**是業界標準，完全可決定性（子種子由主種子派生，並限制最多重抽次數）。

### 1.9 Wonderdraft / Inkarnate 與 Here Dragons Abound（水墨風格）

- Wonderdraft、Inkarnate 是手繪工具，不提供演算法；風格重點：**海岸線的多層外暈（淺色帶）、山脈與樹木為側視符號、紙張紋理、邊框與羅盤**。
- Here Dragons Abound（https://heredragonsabound.blogspot.com/ ；本次無法連線，內容來自記憶與二手描述）：作者以程式生成**手繪風地圖**，要點：
  1. 海岸線：沿海岸等高線畫出帶抖動的墨線，外側再加數層漸淡的平行線（「水線」）。
  2. 山：沿山脊線以固定間隔擺放側視山形符號，近處者擋住遠處者（依 y 排序），符號大小隨高度；多種手繪變體避免重複。
  3. 森林／丘陵用小符號，以泊松圓盤分佈於對應生物域。
  4. 標籤沿特徵（河、山脈）走曲線，並避開符號；以貪心＋評分決定位置。
  5. 水彩效果：以多層雜訊疊加紙張紋理與色塊不均勻。
- PirateMap（https://github.com/kosua20/PirateMap ）：海岸線以「多次繪製、每次加雜訊」得到鉛筆般的粗糙線——可借其簡單的作法。
- 本專案是 2.5D 水墨，山水「符號化」比逐格上色更符合風格，詳見 3.7。

注意：本專案已把雜訊（`noise.rs`）、三角函數（用多項式，6.5 規則 4）、球面 Poisson-disk 自行實作，原因是**逐位元決定性與 WASM/跨 CPU 一致性**。這些外部 crate 多半用 `f32::sin/cos/sqrt/floor` 等；`sqrt` 為 IEEE 精確，但 `sin/cos/exp/pow` 在不同平台可能差 1 ulp。→ 採用前須實測（兩平台輸出雜湊比對），或只用於**不影響存檔結果的部分**（預覽、渲染）。

標籤放置、Markov 名稱：Rust 無成熟專用 crate（以 `markov`、`markov_chain` 之類為主，維護與授權品質參差，未逐一查證）；漢字地名以規則拼接即可（見 2.6）。

### 1.12 學術文獻：構造抬升與河流侵蝕

使用者指定的公開文獻，作為地形物理化的依據。

| 文獻 | 內容 | 本專案用法 |
|---|---|---|
| Braun & Willett (2013), *A very efficient O(n), implicit and parallel method to solve the stream power equation governing fluvial incision and landscape evolution*, Geomorphology 180–181 | 流水功率方程 ∂h/∂t = U − K·A^m·S^n；沿「受水格／堆疊順序」隱式求解，無條件穩定、O(n) | L7 侵蝕的核心：每次迭代依流向圖由下游往上游更新高度 |
| Barnes, Lehman & Mulla (2014), *Priority-Flood: An optimal depression-filling and watershed-labeling algorithm*, Computers & Geosciences 62 | 以優先佇列從邊界（海）向內淹水填窪；ε 變體保證每格都有下坡出路；同時給出集水區標號 | 取代臨時的填窪；彈出順序即流量累積的拓撲序；每次侵蝕迭代前重算以穿越湖泊 |
| Cordonnier, Braun, Cani, Benes, Galin, Peytavie & Guérin (2016), *Large Scale Terrain Generation from Tectonic Uplift and Fluvial Erosion*, Computer Graphics Forum 35(2) | 由抬升圖 U 與流水侵蝕反覆迭代，生成大尺度、樹枝狀水系與真實山脊 | L1–L4 產生的是「抬升圖」而非最終高度；高度由 L7 迭代求得 |

與其他來源的關係：
- 板塊、大陸核、脊距離場、雜訊共同組成抬升圖 U；Cordonnier 的方法把它轉成有水系結構的地形。
- 球面等距圓柱格需處理：東西環繞、極區列的面積權重 cos(lat)（流量 A 以面積計）。
- 迭代次數受 6.8 的生成時間預算限制，依 S／M／L 實測後寫入 7.1。

## 3 對本專案的建議

優先級：P0 立即做（直接解決超大陸）、P1 近期、P2 之後。每項皆須保持決定性（子流由主種子派生，固定處理順序，不用 HashMap 迭代順序）。

### 3.0 分層混合管線（各來源負責哪一步）

板塊、雜訊、模板、渲染不互斥，依「宏觀 → 微觀 → 呈現」分層，每層取最擅長的來源。全部使用 `worldgen` 派生子流，各層用獨立子種子（Dwarf Fortress 的多層獨立碎形），順序固定。

| 層 | 步驟 | 主要來源 | 輸出 |
|---|---|---|---|
| L1 | 板塊分區：球面 Voronoi（經 domain warp）、運動向量、大陸／海洋標記（相鄰者不連選，保證大洲分離） | 板塊（Tectonics.js／WorldEngine 的結果形態；Civ 的分離保證） | `plate_of`、邊界類型 |
| L2 | 大洲骨架：每個大陸板塊內放 1–3 個大陸核（blob），質量不等分；Voronoi 邊界與板塊邊界處加 `rift`／`Strait` 保證海峽 | 模板／blob（Azgaar Hill／Strait）＋ Civ rift | 低頻「大陸層」 |
| L3 | 造山帶：聚合邊界與海岸山脈用**到邊界的距離場** × 脊狀碎形；島弧、海溝、裂谷由邊界類型決定 | 板塊邊界（2.2 現文件表）＋ mapgen4 距離場＋ 脊狀雜訊 | 山脈項 `up` |
| L4 | 細節：fBm ＋ domain warp 決定海岸碎形、半島、小島、丘陵起伏；基底對比刻意小於雜訊，使海岸由雜訊決定 | 雜訊（terrain-from-noise、fastnoise 式 warp） | 完整 `h` |
| L5 | 設計師控制：可選的模板（blob／range／strait 指令序列）與固定「錨點」（例如指定遊戲故事所需的大洲位置）疊加於 L2–L3 | 模板（Azgaar 模板編輯器） | 覆寫項 |
| L6 | 海平面分位數 → 連通分量驗收／補救（3.1） | Civ 驗收重抽、Azgaar 特徵標號 | `continent_of` |
| L7 | 以 L1–L5 為抬升圖，迭代流水功率侵蝕（Braun & Willett 2013 隱式解）＋ Priority-Flood 填窪（Barnes 2014），即 Cordonnier 2016 的抬升＋侵蝕法；再接河流、氣候、生物域、州郡 | Braun & Willett、Barnes、Cordonnier（1.12）；O'Leary、mapgen4、Holdridge/Whittaker 查表、CK3 省界原則 | 最終 `h` 與其餘輸出 |
| L8 | 渲染：海岸折線、符號山水、墨線河、標籤 | Here Dragons Abound、Wonderdraft／Inkarnate、PirateMap | 渲染端資料 |

要點：
- L1 負責「有幾塊、在哪、之間是海」；L4 負責「看起來自然」；L3 負責「山脈有結構」；L5 負責「要什麼就能指定」。
- 現有程式的「大陸核」＝ L2，「細節 fBm」＝ L4，「造山雜訊帶」可保留為 L3 的**局部起伏調製**（取代純結構性山脈的單調感），不必丟棄。
- 已存在的 2.2 板塊設計（邊界類型表、`WG_PLATE_*` 參數）可直接成為 L1／L3；#32 定案時，建議以此表為主、雜訊版 `height.rs` 的大陸核與脊狀山脈作為 L2／L4 沿用。

### 3.1 多大陸（P0，對應現有主要問題）

現況：大陸層為各核高斯丘取最大值，再加細節 fBm；高斯丘尾部與細節疊加後在相鄰核之間易連成陸橋。

建議（由簡到繁，可疊加）：

0. **先由 L1 板塊保證分離**：大陸板塊只挑「彼此不相鄰」者（2.2 現文件的第一輪規則），大洲天然被海洋板塊隔開；以下各項為在無板塊或板塊不足時的補強。
1. **核間裂隙（Civ 的 rift ＋ Azgaar 的 Strait）**：以大陸核（或大陸板塊中心）為站點求球面 Voronoi（只需「最近核距離 d₁ 與第二近 d₂」），在 Voronoi 邊界附近減去 `rift = k·g((d₂−d₁)/w)`，其中 `g(x)=exp(−x²)`，`w` 約 8–12 赤道格（參數 `WG_RIFT_W`、`WG_RIFT_DEPTH`）。這等於把「大洲之間」的海做成確定性的帶，與是否碰巧雜訊連通無關。高度減去 rift 之前用同一份 domain warp 座標，使海峽曲折而非直線。
2. **核的選擇用 Poisson-disk（最小球面間距）**，而不是純隨機；間距 ≈ `0.9·sqrt(4πR²/N_core)`（`N_core` = 目標大洲數 + 若干小核）。已有「彼此隔開」邏輯時，確認間距下限不依賴巧合。
3. **以 area-weighted 分位數定海平面之後，量測連通分量**（已有 `continent_of`）：
   - 驗收條件：最大陸塊 / 陸地總面積 ≤ `WG_MAX_CONT_FRAC`（例如 0.45），且 ≥ `WG_MIN_CONT_COUNT` 塊面積 ≥ 陸地 8% 的大洲（Civ「Small Continents」< 33% 的作法，上限值為我們的假設，須調參）。
   - 不合格時：**補救優先於重抽**——對最大陸塊，找其「最窄處」（以距離場／骨架，或簡化為：沿最大塊內相鄰核連線取高度最大者）施以局部 `Strait`（加深 rift）；補救 N 次仍不合格，才以 `sub_seed = hash(seed, attempt)` 重抽，上限 8 次，之後接受當前結果並記錄警告。這樣平均成本低且絕對決定性。
4. **兩層陸地比例控制**：總陸地比例仍用分位數（保持現狀），但各大陸核的「質量」(`radius`) 用 Dirichlet 式不等分（例如 1 個大、2 個中、2 個小），讓大洲有大小層次，而不是 N 塊等大。
5. **島嶼**：核外細節高點本來就成為小島（現況）；再加一組「島弧／群島核」（半徑小、數量多、沿某條隨機大圓弧排列，加上少量位置抖動），產生島鏈。可放置在大陸核之間的 rift 附近。
6. **domain warp** 已有；保持兩層，但**warp 強度不得讓兩核重疊**。warp 量建議 ≤ 核最小間距的 15%。
7. **不推薦**：提高雜訊頻率、或只調降陸地比例——這兩招只是改變機率，無法保證。

驗證：新增一個測試掃描 200 個種子 × 三種尺寸，斷言「最大陸塊占比 ≤ 閾值」與「大洲數在 [3, 7]」；對照 `quality.rs` 現有品質檢查加入。

### 3.2 山脈與山脊（P0/P1）

現況：造山雜訊等值線帶 × 脊狀碎形。曲折但山脈與大陸結構無關。

建議：
1. **山脊線來源改為結構性**（mapgen4 距離場的作法）：脊線 = (a) 板塊聚合邊界（陸陸聚合＝主山脈，洋陸聚合＝海岸山脈，洋洋聚合＝島弧；即 2.2 現文件表）、(b) 同一大陸內相鄰核之間的**縫合線**、(c) 無板塊時沿某一側海岸的**海岸山脈**（距岸 15–25 格處）。把脊線取樣成折線，施以 domain warp 抖動。
2. **高度 = 距離場**：`mountain = A·(1 − dist_to_ridge / W)^p`，`dist` 用球面弦長，以多源 BFS／Dijkstra 在格點上求（確定性、簡單）；再乘脊狀碎形（`1−|2n−1|`，高八度以低八度加權）賦予細節。`W` 隨機（山脈寬 6–14 格），`A` 隨機（高低）。
3. **山脈長度與斷續**：沿脊線乘一個一維低頻雜訊作斷續（避免一條山從頭連到尾），間斷處就是**隘口**（關隘候選，見 3.5）。
4. **輕量侵蝕**（O'Leary，P1）：山脈生成後做 K 次（4–8）「流量加權的坡度削減」，使山脊樹枝化、谷地貫通；順序固定為高度降冪、格索引決勝。可只在山脈格上做，成本小。
5. 與 2.2「地形」節的 `h` 兼容：不改輸出欄位。

### 3.3 氣候與雨影（P1）

現況：三圈風帶、逐列掃描兩圈、陸高 > 0.62 一次性扣 0.3。

建議：
1. **改成 mapgen4 的連續公式**：沿風向逐格，`humidity += evap·(海)`；`if humidity > cap(elev)`（`cap = 1 − elev·k`）則 `rain = rain_shadow·(humidity − cap)`，`humidity −= rain`。迎風坡多雨、背風坡乾，山越高越明顯，不需 0.62 這種硬門檻。
2. 逐列掃描因風帶為純東西向而簡單；**風帶邊界混合**：在 ±30°、±60° 附近 3–5 度內，兩方向的濕度以 smoothstep 混合，避免條帶斷裂。
3. **大陸性**（Undiscovered Worlds）：距海遠的內陸溫差大、更乾——已有 `coast=exp(−d/10)`，可加溫度的年較差項，供四季事件使用（後續）。
4. **洋流（P2）**：僅以「西岸暖、東岸涼」的經驗常數調整溫度（± 數度的緯向偏移）即可，不模擬洋流。
5. 生物域維持現有「判定順序」規則，但建議改為**溫度 × 濕度的查表矩陣**（Azgaar／Whittaker／Holdridge 風格），資料放 `7.1 參數總表`，便於調參與在地圖上產生合理的過渡（如草原、荒漠、針葉林）。

### 3.4 河流（P1）

現況：priority-flood、D8、累積量分位數分級。

建議：
1. 填窪時**同時輸出拓撲順序**（mapgen4）：洪填時每格記錄「被誰到達」，直接成為下坡指標，省一次排序；累積量按逆序累加，**單趟 O(n)**。
2. **幹流壓低**（mapgen4）：累積量大的格把高度壓低到不高於其所有上游，避免河谷「爬坡」；順便得到谷地形（配合 3.2 的侵蝕）。
3. 流量用 `降水 ^ 2`（mapgen4 的 `moisture²`）放大乾濕差異：乾燥區少河，濕潤區多河，比線性更像。
4. **出海口與三角洲**：河口處向海延伸 1–2 格淺灘，供渲染畫三角洲／濕地。
5. 河流跨越州界作為邊界代價（已有 +6）；另給**渡口**（河上流量較小處）降低代價。
6. 湖的出口只取一個（已有）；加入「內流區」（沙漠中的鹹水湖）可在填窪後保留 `h < sea` 的封閉盆地——可選。

### 3.5 州郡（P1，CK3 風格）

現況：宜居度加權 Poisson-disk → 多源 Dijkstra，代價含丘陵／山脈／大河。

建議：
1. 保持架構（已經是正確方向）；加強兩點：
   - **自然邊界對齊**：代價中「跨山脊線」「跨江」「跨海峽」加大；使邊界落在山脊／河上。再做一次後處理：**邊界格重指派**——對州界上的格子，若其 4 鄰有 ≥ 3 個屬同一個鄰州，歸入該鄰州（去鋸齒，CK3 的省界是平滑連續塊）。
   - **最小面積與連通性檢查**：太小的州（< 平均的 25%）合併進代價最低的鄰州；對每個州做連通分量，孤塊併入鄰州。
2. **州群（郡→州→道）層級**：用同樣方法，對州的鄰接圖做第二層聚類（以州的中心點、同一大洲優先、跨海懲罰），得到「道／州部」，對應三國志式層級；層級不超過兩層（6.x 規則）。
3. **關隘與渡口自動偵測**（P2）：州界上山脈格中最低的通過點（鞍部）標為關隘；州界上被河切開處流量最小的格標為渡口。供戰略與渲染（畫城門符號）。
4. 輸出一份 **鄰接表**（含「經海／經河／經關」類型），存為資料表，不再臨時計算。
5. CK3 的另一個啟發：**不可通行區**（高山、深海）顯式標示，而非以代價無窮表示。已有「海、湖不可通行」，可擴充為「極高山（> 0.9）不可通行」。

### 3.6 命名（P2）

現況：7.3 / `naming.rs` 以儒釋道混合詞庫與規則拼接（未逐檔核對）。

建議：
1. 中文地名不適用字元 Markov 鏈；改為**結構化模板**：`[修飾][通名]`，通名依地貌（山／嶺／峰、江／河／溪、湖、澤、原、關、津），修飾詞按**文化／三教風格**取詞庫。這比 Azgaar／O'Leary 的 Markov 鏈更合漢語。
2. 借 O'Leary 的**「語言」概念**：每個大洲或文化在世界生成時，從詞庫中以種子抽出子集（例如 40% 的修飾詞）與偏好（如多用「青、白」或「崑、蓬」），使不同大洲名稱風格自然分化。
3. 借 Azgaar 的**去重與長度偏好**：同名衝突時加方位詞（東／西／南／北／上／下）或序數；避免相鄰州同字開頭。
4. 若要音譯式的外邦地名（可選），再考慮簡單的音節 Markov（以語料音節表為狀態），自行實作 50 行即可，不必引入 crate。

### 3.7 地圖渲染與標籤：水墨風（P1，與美術同步）

資料準備（sim 端輸出，渲染端消費）：
1. **海岸線折線**：用 marching squares 對 `h = sea` 抽等值線並平滑（Chaikin 兩次）；格點東西環繞需處理接縫；輸出為折線集合（每個大洲／島一組、湖另一組）。這比逐格貼圖更適合墨線與外暈。
2. **海岸暈染**：沿折線向海一側以距離場做 3–4 層漸淡色帶（Here Dragons Abound、Wonderdraft 共同的特徵）；以 shader 實作（見 8.4 著色器），資料只需「到岸距離場」（BFS，格點上容易）。
3. **山水符號**：沿山脈脊線（3.2 已有）以泊松圓盤布點，`y` 排序畫側視山形；符號大小 = 高度；符號集 6–10 個變體，種子決定選擇；丘陵／森林同理用較小符號，依生物域密度布點。這是水墨風的核心，也比平鋪貼圖便宜。
4. **河**：用流量等級決定筆寬（小河 1、大河 2、江 3），沿折線畫「飛白」變寬線條；河線用 Chaikin 平滑。
5. **紙張與水墨濕暈**：全螢幕後處理（噪聲紙紋、邊緣暈），與地圖資料無關。
6. 標籤（P1–P2）：
   - 候選位置：州中心、山脈脊線中點、河口、島中心。
   - 評分：與已放標籤的重疊（重則禁）、與符號重疊（降權）、離特徵遠近、所在格地形平坦（O'Leary 的準則）。
   - 山脈、江河標籤沿曲線排列；漢字**直排**（中國畫風）可沿折線每字旋轉；字數短，成本很小。
   - 貪心＋少量擾動即可，不需模擬退火；順序按重要度（大洲 > 州 > 山河 > 城）固定，保證決定性（標籤屬渲染層，不影響存檔，但仍建議確定）。
7. 這些資料只在**渲染端**或載入時生成，不進存檔；以 `seed` 重現即可。

### 3.8 採用的 crate，而非自寫（P1，附條件）

| 需求 | 建議 | 理由與條件 |
|---|---|---|
| 噪聲 | 維持現有自寫 `noise.rs` | 逐位元決定性與 WASM 一致已解決；若要擴充 domain warp／Worley，可評估 `fastnoise-lite`（MIT，純 Rust，內建 warp 與 Ridged）或 `libnoise`，但須在兩種 CPU（x86_64／aarch64）與 WASM 上對輸出做雜湊比對再採用 |
| 三角剖分 | `delaunator` 1.1（ISC，維護中） | 若要把州郡改為 Voronoi 或做州鄰接三角網，可用；格點方案下暫不需要 |
| Voronoi | 不採 `voronoice`（2022 後無更新） | 需要時用 `delaunator` 自算外心 |
| Poisson-disk | 維持自寫球面版 | `fast_poisson` 僅平面，不含球面與環繞 |
| RNG | `rand_chacha`（已用） | 最佳確定性 |
| 等值線 | 自寫 marching squares（約 80 行） | 需處理東西環繞；crate（`contour`、`isoband`）未查證維護狀況 |
| 標籤／Markov | 自寫 | 無成熟 crate，需求也小 |

結論：**現階段不需要新增依賴**；主要工作是演算法層的改進（3.1–3.5）。
